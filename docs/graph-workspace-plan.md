# 常驻图谱工作区与密集表格

状态：本地源码候选，2026-10-15。按本次用户约束，**左侧与顶部区域始终常驻，不提供折叠、展开、抽屉替代或图谱专注隐藏模式**。本页替代上一阶段的折叠方案。独立 Electron 的运行、构建及证据边界见 [desktop-delivery.md](desktop-delivery.md)；本次没有修改 Analytix。

## 空间与操作重排

图谱是主工作面，通过压缩固定宽高、对齐表单和合并低频任务入口增加面积，不以删除功能、无限缩小字号或把业务动作全部变成无文字图标来换取空间。

| 区域 | 当前安排 | 保留的功能与边界 |
| --- | --- | --- |
| 左侧 | 320 CSS px 常驻；查询字段双列，金额与时间区间整行；查询／重置并排，批量追踪参数紧凑排列 | 账号、户名、对手、关键词、金额、时间、已上图、分页和批次入口保留。表单与结果在各自滚动范围内可达。 |
| 顶栏 | 44 px；品牌、案件切换、案件管理、导入、数据工具、分析、导出集中排列 | 高频入口直接可见；数据变更、显示操作和危险动作仍有明确名称与分组。 |
| 图例／范围 | 25.5 px 紧凑状态行 | 保留账户角色文字与邻域／全图范围，不能只凭颜色判断角色，也不能隐藏当前视图范围。 |
| 图谱工具 | 78 px 两行：画布／保存／布局／显示；中心账号／方向／邻域／缩略图／标签 | 重新布局、适应画布、邻域展开和返回全图保持直接可达。保持现有控件 ID，图算法和金额契约未因重排改变。 |
| 低频业务动作 | 六个具名对话框：案件管理、数据工具、导出、画布管理、图谱显示、主账号 | 对话框是业务动作组合，不是左侧或顶部的区域折叠。删除独立分组；关闭后焦点回到入口，关闭不提交操作。 |

本次浏览器在 **1280×900 CSS 内容视口**测得图谱 **960×752.5，约占 62.7%**；上一候选为 900×623、48.7%。这是指定内容视口的面积结果，不能外推为 Electron 原生窗口总面积、Windows DPI 或所有窄窗结果，也不是交互延迟提速证明。

不再保留“收栏后超过 80%”“图专注隐藏查询”等目标。宽度不超过 700 px 的网页视口使用上下常驻、允许滚动的排列，无法同时提供大图和完整查询；桌面默认最小宽度为 960 DIP，但创建时会按实际工作区缩小尺寸及最小值，避免高 DPI 小工作区越界。长中文、长案件名及页面缩放仍须保持控件可达，不用关闭可访问缩放掩盖布局问题。Windows 实测状态见 [desktop-delivery.md](desktop-delivery.md)。

## 左下流水表保留七列

仍使用原七列表格：**勾选、交易时间、付款方、收款方、金额、摘要、操作**，不改成卡片或账本 Grid。保留查看详情、上图／下图、勾选及批量追踪等操作。

- 表头吸顶，勾选列固定在左侧；38 px 数据行、10 px 表格字体、24 px 操作按钮。时间拆成日期／时分秒两行；付款方和收款方各 78 px，摘要两行，操作合并为同一行的“上图／已上图”和“前后”。
- 付款／收款身份按原列对照，账号和名称省略显示时提供完整 `title`；金额完整显示、数字对齐，不截断或缩写大金额。
- 全部列保留，横向滚动只发生在表格视口内。普通合成数据实测表宽 471.1 px，完整巨额金额时为 524.9 px；最终 296 px 可滚动视口的横移范围分别约 175／229 px。与上一版 729／781 px 相比减少移动，不能承诺窄左栏同时放下所有列。
- 底部 28 px 自有水平滑轨始终可见，支持拖动、左右按钮、方向键、PageUp／PageDown、Home／End；真实滚动、重新查询和容器变化均同步位置，无溢出时保留但禁用。Chromium 隐藏重复的系统横条；纵向条滚动时出现，停止后 800 ms 隐藏，鼠标或焦点停留不使其常亮。
- 查询条件独立滚动，表格、水平滑轨和分页各占自己的空间；960×640 最小桌面内容视口检查未将底部控件挤出。短窗仍可滚动访问查询条件，不提供区域折叠。
- Tab 可定位行与操作，空格勾选，Enter 查看详情；表格滚动、焦点、选中态和当前案件必须一致。功能检查不等于完整屏幕阅读器合规。

浏览器合成流程已检查 5000 节点案件及大金额边界筛选，指定边界返回 1250 笔；新 Blob 下载的 XLSX 回读具有两张工作表、4999 条追踪流水，金额为精确字符串。Electron 合成 200 节点／199 流水也检查了新表格和水平滑轨，原生保存的 XLSX 逐行核对付款／收款、币种和精确金额。截图、尺寸、导出回读及资源指纹保存在 `output/desktop-workspace/`。这些证据不替代所有业务筛选或 Windows 文件保存验收。

## 尺寸、标签与性能边界

图仅观察自己的最终容器，保留 `min-width:0`／`min-height:0` 和现有 ResizeObserver 生命周期。容器改变时须复核图坐标、裁剪和 minimap；不能因打开业务对话框清空选中、重跑资金查询或自动覆盖手工布局。CSS px、Canvas backing store、DPR 与导出分辨率分别处理。[ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)

边标签继续采用透明背景，透明命中矩形仍服务选中／拖动；完整金额、来源、保存坐标与全部标签／导出模式不变。现有有界 bbox 筛选、端点遮挡检查与密集线策略见 [graph-render.md](graph-render.md)。本次空间重排没有引入新的碰撞算法，也不承诺任意密图无重叠。

若后续增加标签位置试探，只在当前有限候选集内按预算检查；不在每次 wheel 对 5000 节点和全部关系做两两碰撞。手工位置与自动结果分开，案件／画布失效后拒绝旧回调。减少动效时保留状态反馈，不使用持续动画掩盖绘制成本。[减少动效](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)

## Analytix 与公开方法的取舍

此前研究固定到 Analytix commit `c7d2a370855a8d371c61c32cc2422515b9404ef2`，本次未刷新或运行其源码。可继续吸收容器测量与销毁配对、主次命令一致、标签测量后避让等机制；本次明确不采用其收栏行为，不复制工作区 store、案件 authority、PII projection 或主进程。历史源码引用和插件缺口见 [windows-and-plugin-plan.md](windows-and-plugin-plan.md)。

官方 [WAI Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 提供焦点、Esc 和返回入口的交互依据。当前使用原生按钮和自然 Tab 序，不仅为外观添加 `role=toolbar` 却遗漏键盘模型。

[G6 auto-adapt-label](https://github.com/antvis/G6/blob/c4fc050c/packages/g6/src/behaviors/auto-adapt-label.ts) 的优先级／bbox 机制仍只作 G6 5 的跨版本研究；[D3 forceCollide](https://d3js.org/d3-force/collide) 只处理圆形软碰撞，不能证明边标签或资金路径可读。本次不增加这些依赖或复制实现，不以星数、示例图或默认参数证明更好。

下一步先以“查询→勾选追踪→邻域→详情→保存／导出”的实际任务检查密度与可达性，再推进真实 Windows 的混合 DPI、中文路径和系统保存。继续保留 G6，不重写 Rust。进入 Analytix 时复用共享 React 面板和真实 Host adapter，独立 Electron 与第二个数据库不整体搬入宿主。
