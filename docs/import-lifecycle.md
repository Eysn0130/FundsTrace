# 导入任务、来源追溯与上传留存

文件夹整包、卡账与子账户证据、节点投影及统一统计口径见 [文件夹导入与来源证据关联](folder-evidence-import.md)。

任务及来源的运营时间统一保存为 UTC，并在 API 中带 `Z`、界面中标注 UTC；这不改变原始交易时间，也不补猜历史交易时区。

本文描述当前独立 FundsTrace 的实现与操作入口，不是 Analytix Host 接入合同。原 `fund-tracker` 目录及业务数据保持不动；桌面安装验证与公开版本见 [桌面交付](desktop-delivery.md)，不修改 Analytix。

## 统一服务与持久状态

[app/services/imports.py](../app/services/imports.py) 统一管理 v1 与 legacy 导入；[app/importer.py](../app/importer.py) 保留识别、资金清洗、案件内去重与写库算法。路由不再各自维护后台执行或进程内任务字典。数据库连接、共享锁与嵌套事务仍由 `db.py` 拥有，没有第二个数据库写入者。

| 对象 | 职责 |
| --- | --- |
| `import_sessions` | 案件／surface 绑定、文件摘要、映射、冻结请求、状态、尝试次数、到期时间与回执 |
| `import_sources` | 文件名、SHA-256、大小、模式／映射、工作表、解析器版本、行号口径、导入时间与来源类型 |
| `import_source_operations` | 与解析器身份规则独立的来源—批次及有效状态；与成功回执同事务保存 |
| `flow_sources` | 本案流水与源记录位置的关联，区分 `imported`／`duplicate` |
| `import_file_gc` | 注册上传的持久删除队列，带摘要；删除失败可再次处理 |

文件名和 ID 只是选择器，不授予访问权限。服务核对案件、surface 与已登记记录；不从 uploads 文件名重建授权。v1／legacy 不互相接管会话，同案来源查询则反映共同流水事实。旧缓存／内存任务不被扫描成新会话。

上传文件名先去掉路径，再按真实扩展名选择解析器；显示名超过 240 字符时只截短主体、保留扩展名，不因截断接受不支持的类型。无扩展名文件沿用 CSV 解析，预览、提交和来源验证保持一致，来源仍记录该无扩展显示名。

## 回执、回滚与明确恢复

```text
上传预览成功 → ready → 用户确认 → parsing → importing → done
                                 └──────────失败 → error
error／ready → 用原文件重新预览 → ready → 用户确认后再次提交
重启发现旧进程 parsing／importing → error(import_interrupted)
```

提交保存本次模式、映射和主账号选项，`attempt` 加一。活动或已完成会话再提交返回 `started:false`，不覆盖冻结请求、不启动第二个任务。回执区分新增、重复、跳过与批次；进度 `done/total` 是处理量，不能当新增笔数。

单文件表格 v69／XLS v70／事件证据 v71 新增完整 39 列调证模板的交易号与凭证引用分离；旧版本及 ZIP／RAR 成员规则保持原解释。未编目表格在同一区域含交易流水号与凭证号且有候选冲突时，React 会先保留预览，用户可在「高级：调整解释」选择「凭证号作为独立引用」后重新预览，也可沿用默认规则继续。该选择只分离凭证号／凭证编号，其他交易号候选仍须一致。

v1 重新预览的 `reference_policy` 省略表示沿用当前选择，`null` 明确撤销，`transaction-reference-v1` 明确启用；选择随待确认会话和提交请求保存，关闭重开或失败重试仍需核对预览后确认。提交不得直接改变尚未预览的策略。旧表格 profile、legacy、目录及 ZIP／RAR 入口传入启用策略会明确拒绝；没有凭证列的新版单文件选择不会改变结果。已完成回执仅查询，不重新解释或重放导入。

写入事务涵盖流水、批次、主账号、来源摘要／关联与成功回执。可处理异常使这一组写入一起回滚，再记录安全错误码。解析使用经摘要验证的匿名快照，避免验证后重新按可替换路径读取；下载同样发送校验快照。客户端不接收异常原文、服务器路径或 traceback。

G6 的 `/api/flows`、GET `/api/graph` 和 POST `/api/graph/view` 在支持只读事务的引擎上使用一次请求私有的已提交快照；UTC可比检查、页数据或节点／边、金额汇总、事件、来源装饰及分析版本号来自同一提交状态。导入尚未提交时可返回上一完整状态，后续请求才读取新提交。这三个入口共用单读者准入，连接创建至关闭均受约束，可与原单一写者并行；不建立连接池，v1及其它入口、导出或写操作内部调用图数据的原锁契约保留。私有上下文拒绝共享连接、写入口及非单条SELECT，异常后关闭连接并清理线程状态。

新案件或旧库缺少分析版本号时，先退出只读快照，在原共享锁和事务内初始化，再完成受锁查询。引擎明确不支持只读事务语法时也关闭私有连接、回退完整旧路径；其它连接或查询错误正常传播。数据库初始化完成后才允许建立私有读取。导入临时调整的DuckDB优化器设置是全局的，读者不自行覆盖它。该能力的并发、精确金额及资源证据见[性能记录](performance.md)，不构成跨请求统一快照或Windows验收。

初始化 schema／兼容迁移在同一事务完成，随后 checkpoint 成功才发布连接并接受任务；初始化失败关闭连接。启动恢复将旧进程遗留活动任务标为中断错误，不自动重放。用户重新预览、核对后确认，才产生新尝试。成功回执可重读，不重新导入。

G6 工作区重开时读取当前案件最近的中断／活动任务。中断任务恢复原件预览与上次提交的映射、补充账号和主账号选项，仍须用户确认；活动任务仅读取进度。普通待确认预览和其他错误可从「案件与导入 → 导入记录 → 在 G6 工作区查看」接续；跳转携带案件和原任务 ID，加载后消费任务参数。显式取消全部主账号的空选择不会被重新预览覆盖。切换案件或打开新导入会话后，旧恢复响应不再写入当前界面。

### 多文件队列与目录组

G6 普通文件选择支持多选，逐个执行上传、预览及首次自动确认，前一项取得完成回执后才开始下一项。每个文件有独立任务和结果；需要人工确认的项保留任务 ID，队列处理完后可继续确认，或从本案导入记录恢复。整个文件夹仍作为一个关联组，保留成员目录关系；普通多选不会自动合成大归档。React 工作台普通入口当前明确拒绝多个文件或多个独立文件拖放，提示使用画布工作台多文件入口；其整目录入口保持原有分组语义。

队列只在页面内存中保留待上传文件，不持久化浏览器 File 对象；完成或跳过后释放对应引用。“停止后续文件”、关闭弹窗、切换案件或离开页面均不再启动后续文件。已提交的写入仍按完整事务和持久回执结算，不能把关闭页面或中断前端等待当成服务器已取消。已上传 ready 任务可显式恢复确认；未上传文件需重新选择，重开界面不会自动重放队列。

只有明确分类的文件格式失败允许队列继续。legacy 预览错误保留原 `detail`，另以 `X-FundsTrace-Import-Error-Code` 和 `X-FundsTrace-Import-Failure-Kind` 响应头提供机器分类；未提供分类时默认为未知，不能仅凭 HTTP 400 或提示文字放行。服务层检查格式异常的完整原因链，被包装的内存、磁盘、数据库或其他未知异常不作为可跳过文件错误。写入失败或网络结果不明时停止新调度，仍可按原任务核对状态，不自动重试提交。

普通文件和目录的首次预览共用一个进程内准入槽；已有任务占用时返回 `409 preview_busy`，不排队保留更多解析计划。大小核验、识别、解析、原件保存及登记在后台线程完成。直接使用框架已接收的可寻址上传文件；目录在校验成员路径和大小后，流式构造操作私有临时 ZIP，仍按一个关联组解析。框架在进入服务前已处理 multipart，该准入不是新的 HTTP 请求体限流。既有重新预览的事务路径不变。

成功解析后才以 1MiB 块复制保留原件并计算一次摘要，再在事务内重检案件、登记 ready；输入大小、成员和展开量限制保留。主动取消先等待工作线程释放请求文件：解析后、复制期间及登记事务开始时检查取消，并清理本次暂存/原件；通过事务开始检查后到来的取消允许结算成 ready，不自动确认。当前 Uvicorn 的普通请求在 TCP 断连后仍会完成预览登记；原件由 ready 记录持有，attempt 仍为0。不能把断连或关闭前端当作服务器回滚。文件落盘与数据库登记之间仍存在跨系统崩溃窗口，不通过扫描未知文件补造会话或自动删除。

本轮真实进程恢复回归覆盖新库／旧照片及关注节点结构升级库，分别在未提交写入中 `os._exit(79)` 和已提交回执后 `os._exit(80)` 退出：四项通过。这个证据针对**正常完成初始化后**的导入进程退出与重新打开；不证明迁移中断电、磁盘损坏或任意强杀下绝不丢失。完整测试与浏览器结果以本轮主交付报告为准。

`source_available` 是廉价文件存在／类型提示，不是完整性认证。`recoverable` 表示错误状态下存在可尝试重新预览的注册文件；实际操作仍检查摘要和大小。文件缺失、篡改或已清理时重新上传，不凭恢复标志绕过核验。当前是一个服务进程与后台线程，没有跨进程任务队列。

## 有限的纯解析结果复用

整包暂存可在预览完成后由当前进程保留一份、最长60秒。保留前比较案件绑定前后的完整SQLite文件摘要及解析元数据；只有二者完全一致的纯解析结果才合格。案件校验改动记录、流水、统计、成员或其他解析元数据时不复用。保留的是同一暂存所有权，没有复制第二份完整计划；沿用单计划8GiB磁盘上限及有限解码缓存，额外可签名元数据上限16MiB。开始新解析先释放旧槽位，不累积多个待确认预览。

服务返回的预览响应元数据与内部缓存计划脱离；修改返回的映射、统计或成员摘要不能改变已经封存的计划。仅复制已构造的响应，不复制整批流水或暂存。内部缓存篡改仍按完整性错误失败，不降级为静默重算。

提交仍核验注册原件的SHA-256、大小和普通文件类型，并生成原件快照；缓存键还核对任务、案件、surface、文件、映射、列、解析配置。取得缓存会从槽位移走唯一所有权，并再次校验完整暂存摘要；损坏拒绝本次写入。随后在既有写入事务中重新执行当前案件的历史范围、冲正、去重及完整性检查，来源、操作关系与回执仍原子保存。缓存不提供案件判定或新的写入权限。

重预览会先释放旧结果；缺失、超时、被新预览替换或重开后的缓存均从核验原件重算。明确到期上传清理、启动恢复、正常进程退出也释放当前槽位；用户放弃确认时最多保留60秒，不自动提交。强制终止进程可能遗留原有类型的操作暂存目录，但重开不加载它、不据此自动重放，也不扫描未知目录授权删除。正常退出与强制退出后明确提交的合成进程回归分别覆盖这一边界；护栏终止后的清理由运行器仅针对已确认归属的暂存处理。

成员进入暂存前累计整包统计，避免再解码完整计划求同一统计；运行时将无机构声明的操作范围与来源位置绑定共用一次遍历。直接解析调用的默认结果不变；后续案件绑定若撤销范围或变更来源引用，既有完整读取及引用验证路径仍执行。原件解析版本、金额、来源位置和判定含义未变。

## 从流水回到来源

每个受管理上传有独立来源 ID。新流水关联首次来源；同案重复记录关联到已存在流水，保留本次文件和位置，不增加原始流水笔数。另一案件独立处理同一文件，不能借用原案来源／流水 ID。

所有当前托管新导入（包括普通表格、legacy 入口和 evidence profile）均记录独立操作关系。删除批次只撤回该次导入的有效支持，并在同一事务内重建身份、卡账与事件结果、使分析缓存失效。同一流水仍有其他有效导入的来源链接时，保留流水 ID、原字段和图上引用；最后一份支持撤回后才移除流水及图上引用。重复批次即使新增笔数为零，也可能提供有效支持。

`flows.batch_id` 是现存流水的存储归属：删除原归属批次但仍有有效支持时，改归剩余有效批次中 ID 最小的一项，仅用于保持引用完整，不认定该批次最早、最可靠或改变交易事实。历史导入回执、原文件及其 SHA 保留，来源日志沿用 `removed/flow_deleted` 表示该次导入与流水的链接已撤回。案件包的操作关联与兼容规则见[案件包格式与兼容](#案件包格式与兼容)。本地旧库只从明确 evidence 关联，或同案、同来源 ID、同摘要/大小且成功回执中明确的 source_id/batch_id 迁移。已退休批次的回执只能撤去旧残留链接，不恢复流水；无法核对关联的历史来源保留原归属删除行为，不从文件名或相似字段猜补支持。普通新上传不属于这个历史缺口。

解析器 `funds-trace-table-v4` 在全列去重指纹中保留交易时间的完整微秒；同一秒内其他字段相同但微秒不同的记录是不同流水。去重时从本案已存流水的真实列重建指纹，不增加 schema 或改写历史来源版本。旧解析器已经合并而未保存的交易无法由现存数据推断或自动补回，需取得原始文件并重新预览、核对后导入。

模式 B 每行必须有可识别的收支标志，或现有收入／支出金额列证据；空白或未知标志且无该证据的记录计为跳过，样例说明“收支方向无法确定”并保留可确定的 `source_row`。有效收支标志优先、收入／支出列回退与金额解析规则沿用原契约；金额正负号本身不授予方向，非正交易金额仍计为无效。

位置口径为 CSV 逻辑记录序号（含表头与空记录；引号内换行仍是一条记录），或 Excel 选中工作表实际行号。`unknown` 明示未标定口径。来源还包含原文件名、SHA-256、字节数、模式／映射、工作表、解析器版本和导入时间。

解析跳过样例在可确定时带 `source_row`，但样例不等于完整无效行审计存储。历史流水或没有可靠来源的旧 `commit_rows` 调用保留“未记录来源”，不能推断原文件、伪造摘要或为旧行补顺序号。

原文件下载核对本案来源／会话、摘要、大小及普通文件类型，拒绝 symlink。包来源没有本地原始上传，不提供下载；原件清理后来源元数据仍在。

## 7 天／30 天与显式清理

| 状态 | 到期时间 | 保护规则 |
| --- | --- | --- |
| 上传预览成功 `ready` | 上传后 7 天 | 仅未被引用的注册上传可清理 |
| 重新预览成功 | 从该次预览起 7 天 | 撤销旧 GC 队列并续期 |
| 完成 `done`／失败 `error` | 终态记录后 30 天 | 回执／来源元数据不随文件清理删除 |
| 启动标记中断 | 标记后 30 天 | 留给明确恢复，不自动重试 |
| `parsing/importing` | 活动期间保护 | 原到期时间已过也不能清理 |

到期只是最早清理资格；没有定时自动清理。任何现存 `flow_sources` 引用都继续保护源文件，30 天不覆盖引用保护。删除批次去掉对应引用后才可能按已有到期时间清理；删案在事务内登记上传 GC 再移除案件记录，原文件随后由全局清理处理，不能视作同步擦除。

清理与提交使用同一共享锁，删除前重新核对任务、引用、到期状态、摘要及类型。失败保留队列；续期后旧队列不能提前删除文件。未知文件／目录、symlink 及摘要不符的替换文件不会被盲删，需要另行核实。文件删除和数据库更新有队列补偿，仍不等于跨系统断电原子事务。

React／API 可处理当前案件；CLI 可处理全局队列。CLI 必须显式指定含 `fund.duckdb` 的管理运行目录，先关闭使用同一库的服务并确认维护范围。不要用原业务目录试验新候选。

```sh
# 预览删除计划，不执行文件删除
.venv/bin/python scripts/cleanup_imports.py --data-dir /absolute/path/to/managed-runtime --case-id 2

# 执行本案符合策略的文件删除
.venv/bin/python scripts/cleanup_imports.py --data-dir /absolute/path/to/managed-runtime --case-id 2 --apply

# 全局处理，包括已删除案件留下的 GC 队列
.venv/bin/python scripts/cleanup_imports.py --data-dir /absolute/path/to/managed-runtime --apply
```

`--case-id` 只接受仍存在案件；省略时包括未绑定 legacy 会话和已删案 GC。默认 dry-run 不执行 unlink，但会打开并初始化管理数据库，不能称整个命令只读。输出 JSON；清理 `failed` 或服务错误使退出码非零。需要的原件应有合适留存，不能由摘要重建。

## 界面与案件包

构建后的 `/workspace/` 提供“导入记录”，显示本案最近 100 条会话、进行中进度、完成回执及“继续导入”。继续时先用保存映射重新预览，确认后才写入；关闭进度窗口不取消后台任务，重新打开可查询。legacy 项导向同案 G6 工作区，不跨 surface 恢复。

“导入记录 → 到期上传文件”先预览清理，再确认执行；服务执行时重新判断资格，预览计数不是锁定清单。“流水核对 → 来源追溯”显示摘要、位置、首次／重复关联及原文件下载；缺失来源／原件有明确提示。换案废弃旧请求与显示状态。G6 保留，没有 Rust 重写。

### 案件包格式与兼容

案件包的格式号与解析 profile、派生规则版本、应用版本分别维护。导出按下表从上往下选择第一个满足的条件；不是把所有案件统一升级为最高格式。

| 优先级 | 格式 | 当前导出条件 | 保留的关键内容 |
| --- | --- | --- | --- |
| 1 | 7 | 任一流水 `trade_time_utc` 非空 | 来源壁钟、原文、偏移和 UTC；仍保留实际存在的来源、日志、证据和操作关联。 |
| 2 | 6 | 无上述有区流水，存在独立导入操作关联 | 来源与批次及 `active` 状态；已撤回操作也保留支持生命周期。 |
| 3 | 5 | 无前两项，存在身份解析规则来源 | 显式 `evidence_sources` 及状态；可含相应表格日志。 |
| 4 | 4 | 无前述条件，存在 `table_record` 来源 | 自动表格的来源、成员和逐记录处置。 |
| 5 | 3 | 无前述条件，存在专用反馈冲正规则来源 | 对应来源及冲正解释日志；不按当前冲正条数判定。 |
| 6 | 2 | 其余案件 | 原业务内容及已有来源元数据、行关联。 |

当前导入器接受格式 1–7，但仍完整校验各格式的列、路径、来源版本、日志和引用关系。格式 7 可同时包含有区与无区流水；其中有区记录逐笔验证原文、壁钟、偏移与 UTC 一致，无区记录仍保留原壁钟、不补时区；有来源表时还须有独立操作关联。格式 6 必须保留来源、批次与操作状态的一致性：有效操作须关联仍存在的批次，已撤回操作不得指向仍存在的批次或保留活动来源链接；有身份证据时还须与其状态一致。格式 5 已有的显式证据操作可以迁入独立操作关联；普通旧包缺关系时不猜补。格式 1–6 保持原流水列与历史时间解释，新时间列为空，不把旧时间重新解释为带区时间。具体时间含义见[金额与时间契约](money-contract.md#交易时间与记账时间)。

当前导出格式 2–7 的 `meta.json` 将 `source_files` 明示为 `not_included`；格式 1 继续按原元数据合同接纳。包保留适用的业务内容、来源元数据及关联；**不含原始上传字节、导入会话、后台任务或回执**。恢复创建新案件，重映射来源／流水等 ID，来源标为 `origin=package`，并从已保留的合法来源声明重建派生投影；不凭摘要冒认本地原件。当前导出不再选择格式 1；仍接受合法历史格式 1，无来源时不补造。旧客户端只可使用其实际支持的格式和语义，不能以改 `meta.json` 或删除新表来降级。案件包不能替代完整运行数据与原始文件备份。

## 2026-10-18 · 身份证对照表与演示数据

G6数据工具复用顶栏二级菜单；导入确认面板位于原生顶层，锚定按钮且不占用画布布局空间。选文件后仍需显式提交。身份证对照表作用于当前案件全部画布的同账号资料，只更新身份证号，不更新户名、原始流水或上图集合。界面保留真实处理／无效／空账号计数；支持XLSX、CSV、TSV、TXT，缺少读取依赖的旧XLS在写入前明确拒绝并提示转为XLSX。

未保存账户资料、进行中的账户写入、照片裁剪与其他冲突写入会阻止批量覆盖；批量写入期间账户修改及流水导入提交也不能绕过互斥。流水导入独立记录已发送任务的案件租约，通过原任务进度只读核对，不因关闭窗口或重绑就释放未知写入。重复点击不重复发送。身份资料完成后原地刷新当前图元的资料与标签，不重新加载或适应图谱。

每次操作捕获案件及代次；旧文件选择、旧响应、旧错误在切案后失效。传输失败或不确定回执不自动重试，只能读取当前资料并显式核对结束；读取事实不冒认原操作成功。演示数据有独立确认范围，新增当前案件流水、跳过重复，不自动上图，不能沿用身份证覆盖说明。
