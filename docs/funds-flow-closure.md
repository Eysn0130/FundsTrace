# 原操作资金追踪与代表卡闭环

本轮基于 `b33feb430ec5a056c8f770ee0d7f6094141fd33d`，堆叠在 #82 之上；保留 #81/#82、原工作区和业务原件。未合并、正式打包或发布。真实来源、独立 gold、运行数据库、处理报告与性能明细只留本地，不进入仓库。

## 最终行为

- 原批量来源/去向追踪使用本方账簿、币种、时间及共同来源的明确记账顺序。同秒未知或跨来源不可比时不按导入 ID 推断先后；最近 X 的边界不能任选同刻项。确认事件可以定位另一方的本方观察，但不能借用对手账簿的顺序。小数秒保持原精度。
- 原“前后流水”和“追踪上图”调用条件本金服务。候选范围仍来自当前操作，竞争分录来自完整已记录本方账簿，包含未上图交易。多个入账候选分别计算，不相加独立上界；关系探索、条件范围、FIFO 和实际来源认定分别表达。没有新增入口、条件表单或配置项。
- 代表卡取自当前案件、画布及生效时间/关系范围的最后一笔明确端点卡；后续缺卡不覆盖较早明确卡。同刻不同卡仅在本方共同来源记账序号可比时排序，否则稳定选取并说明并列，不声称银行当前有效卡。无带时间卡时稳定选取有据交易卡，再回退可靠关联卡、账号。
- 历史行保留当笔卡号、来源账号和原始缺失；同实体的新旧卡及账号可查询。节点标签、当前图谱详情与统计使用同一范围，身份和主账号元数据刷新不覆盖该范围。视口、缩放、分页、待提交查询不是业务范围。
- 原生同文本卡/账号关联仅接受同 family、完整请求路径、精确机构及合法角色中的明确 typed 辅助声明。父账户声明不等于选择某个子账；子账号及币种独立。已验证声明先回放，避免同一观察的弱来源与明确来源因遍历顺序形成不稳定冲突；未知机构及相反声明仍保留。删除最后支持后回退，原字段不改写。
- 派生端点新增当笔卡/账号/状态，旧数据库按派生版本重建，旧审计修订保留。分析策略升级使旧分析/导出修订失效。XLSX 保留全画布追踪范围，增加当笔卡号和来源账号列；图像/HTML/PDF仍按现有当前图谱范围导出。两者范围不混称。
- 账户和图谱的总计、付款侧、收款侧、账户对汇总共用一次 SQL 分组，减少重复规划；资金观察及确认事件规则不变。代表卡只读取调用方限定的原观察，保留双边镜像范围。没有用缓存、直接插库或变换查询键掩盖延迟。

## 真实来源与性能证据

每次受控运行使用独立目录，固定 **4 GiB 进程树 RSS、12 GiB 临时盘、600 秒**；采样峰值不是瞬时最大值。原件运行前后校验，未上传。只有同候选、同 runner 的前级完整通过收据才允许升级。

首轮候选小链 10/10 完成适用公共检查，889 次 HTTP，核对 12,738 条接纳观察、487 条追踪/导出观察；34.705 秒，采样树 RSS 887.5 MiB，临时盘 69,058,560 字节。六案具有非空图谱/上下文/导出，三案纯辅助资料，一案缺双端无法上图；不把不适用项算成图谱成功。此小链选取完整原成员及上下文，**不是 99 原包验收**。

首次完整请求验证在第一案 typed parent 关系未建立而停止；776 条接纳、1 条负金额拒绝已单独核对。根因是将明确同域父账户声明误当成不允许识别账户；新增合成复现后修复，仍不归入任意子账。

## 仍需区分的边界
