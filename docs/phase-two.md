# FundsTrace 第二阶段实施记录

日期：2026-10-14（America/Los_Angeles）。工作目录为 `funds-trace`；产品名固定为 **FundsTrace**。本轮只做本地源码、合成测试、性能采样和界面试点，没有修改 Analytix、上传 GitHub、提交或正式打包，没有重写 Rust。

## 本轮完成的纵切

版本化 `/api/v1` 覆盖案件列表／创建、按币种统计、流水过滤分页、绑定案件的上传预览／重预览／提交／进度。Python schema 是来源，生成 `contracts/openapi-v1.json` 和 `contracts/api-v1.d.ts`，可用 `scripts/export_api_contract.py --check` 检出漂移。金额、余额和 ID 以字符串跨 JSON／TypeScript 边界，缺失余额保留 `null`；多币种不合并成一个没有币种的总额。详见 [API 合同](api-contract.md)。

React＋TypeScript＋Vite 试点位于 `/workspace/`，保留 `/` 的原 G6：案件切换／创建、导入映射与规范化预览、主账号选择、导入结果、流水查询分页和单笔核对可用。“打开 G6 图谱”使用当前案件，刷新保留当前案件。表格按原始流水统计，图谱显示去重另算。

视觉方向是能长期使用的案件工作台：深色窄侧栏固定案件上下文，浅色工作区突出流水，金额右对齐，操作分为导入、查询、单笔核对、进入图谱。没有增加完整组件库或更换图引擎。对话框使用原生 HTML `dialog`，支持关闭和 Escape；执行导入期间阻止误关闭。字段改动后必须重新预览；切换单双边模式会清除不兼容映射，日期／时分补充列也可编辑。

`App` 接收一个 typed `FundsApi`，界面与 fetch 传输有接缝，但当前仍是独立产品：它包含原值 DTO，尚不是 Analytix 的安全展示合同。独立页面使用普通 CSS 和本地资源；共享到宿主前需要拆开应用外壳、作用域化样式、safe view model 与 Core protected display，不能直接复制整个页面或原样转发 `Flow`。

## 由真实校验发现并修复的问题

| 问题 | 修复与证据 |
| --- | --- |
| 金额经过 float 后丢分，巨大金额 Excel 回读不一致 | `parse_amount` 保留 Decimal，去重读取原始 Decimal；v1 和追踪 Excel 使用精确文本。新增回归先失败后通过。旧图谱浮点边界仍单列限制。 |
| 缺失币种入库默认 CNY，重导却按空币种比较 | 入库前指纹使用实际会持久化的默认币种；历史真正空币种不重解释。同批及再次导入均覆盖。 |
| v1 上传可经旧接口跨案提交／重预览 | 旧入口拒绝 v1 绑定会话；会话 ID 限十六进制，拒绝 glob；旧进度不提供 v1 案件任务。三个公共回归均有修复前失败证据。 |
| `/api/v1` 精确路径的授权错误与子路径不一致 | 精确路径及子路径统一返回 v1 错误合同，未激活仍失败关闭。 |
| 模式切换残留旧映射；时间补充字段不可修正 | 过滤目标模式的允许字段并要求重预览；两模式开放 `_time2`。界面回归覆盖双向切换和清空。 |
| 百万行后块的 Decimal 列被采样成较窄类型，合法较大金额导入中断 | 资金列使用 nullable text 桥接到目标 `DECIMAL(18,2)`，保留每一位及空值，并由存储类型检查范围。默认采样的 2,000 行回归在金额／余额上均先失败后通过；超出存储范围仍整批拒绝。复现见 [记录](../benchmarks/decimal-sampling-repro.md)。 |

事务、案件包、旧 UI 和原格式仍通过回归。没有改动数据库模式、文件名、`FUND_DATA_DIR`、`.fundcase` 或现有签名格式。

## 可重复入口与证据

后端使用 Python 3.11 与哈希依赖锁；前端实测 Node 22.22.1、npm 10.9.4。命令见 [README](../README.md)。前端构建同时运行类型检查；锁文件与项目 `.npmrc` 一起使用，`npm ci` 已实际验证。基准的正确性、最终源码指纹、分阶段 CPU／壁钟／RSS 及小样本限制见 [performance.md](performance.md)。

后端完整回归、前端组件回归和真实浏览器是分别记录的证据。浏览器使用随机 loopback 端口、一次性目录和公开合成许可，通过正常激活门禁；未连接业务服务。

最终后端命令 `.venv/bin/python scripts/test.py -q --tb=short`：**111 passed，12.80s**，保留 1 条 Starlette/httpx 弃用警告。`npm ci && npm run build && npm test`：安装／类型检查／构建成功，**9 项组件与格式回归通过**；契约导出 `--check` 通过。它们不构成安装或正式发行证据。

修复后基准完成 1 万行 ×3、10 万行 ×3、100 万行 ×1，7 个独立子进程全部完整性校验通过，结果绑定同一最终源码指纹。百万源行中 2 万无效、10 万重复，主案保存 88 万唯一流水；单次 CSV 解析／清洗／首次原子写入分别约 `2.73 / 6.15 / 5.71` 秒，这三个阶段合计 `14.59` 秒；完整 worker 区间 `37.67` 秒，还包含合成文件准备、冷应用启动、重导去重、查询、限量图谱／导出及校验。进程峰值约 `3.18 GiB`。该结果首先支持继续剖析全量物化、去重内存及启动路径；单次容量记录与三次重复尚不支持稳定 P95 或 Rust 重写收益结论。

浏览器已观察：创建“合成验收”案件，上传两行 CSV，金额映射变动后确认按钮禁用，重预览后提交；新增 2 笔、合计 `7754.33`，重复上传新增 0／重复 2，涉及 3 个账号。按 `000SYN-A` 查询为 1 笔；单笔核对保留前导零账号、批次与缺失余额。空白案件为 0 笔，另一个合成案件为 3 笔、合计 `10000000000016400.24`；其中 `9999999999999999.99` 精确显示。三个案件的 API 汇总与独立预期一致。G6 打开同一导入案件并成功上图 1 笔。临时页面及服务测试后关闭。

最后一次资金桥接修改后，另启一次性服务完成受影响导入路径的浏览器回归：2,000 行 CSV 的末行金额和余额均为 `9999999999999999.98`，其余每行 `1.00`；提交回执新增 2,000／重复 0／跳过 0，核对对话框两值均精确，API 为 2,000 笔和总额 `10000000000001998.98`，与独立预期一致。服务退出码 0、临时目录已随退出清理。

合成截图位于被忽略的 `output/playwright/react-workspace.jpg`、`react-import-receipt.jpg`、`react-g6-handoff.jpg`、`react-late-decimal.jpg`。本轮未取得完整移动端、浏览器矩阵、任务耗时对比、跨页表格图谱联动、源文件行级定位、全部导出、Windows 安装或正式发布证据。React 试点可用不等于整站迁移完成。

原 `fund-tracker` 的 6,040 个文件与本轮开始时比对：大小／修改时间 0 变化、新增 0、纳入快照的源码 SHA-256 0 变化。只读取文件元数据与选定源码哈希，没有读取原业务载荷。

## 后续推进顺序

| 优先顺序 | 最小完整下一步 | 进入下一步的条件 |
| --- | --- | --- |
| 1. 导入生命周期 | 把 `main._run_commit` 搬成单一 service，由新旧路由共用；明确任务 ID、重启后恢复／重传、取消点、过期上传清理、失败回执。先记录来源文件 digest、来源行及转换版本的需求和兼容迁移。 | 同案幂等、跨案拒绝、失败回滚／重开、清理不误删仍被引用源文件；没有第二套 importer。 |
| 2. 明确存储与资金语义 | 收敛 service 的全局 DB／目录依赖；为真实 schema 变化建立有版本、可回滚、带旧库合成夹具的迁移。明确币种、时区、舍入、去重与来源追踪语义。 | 各用例的事务仍完整，旧库与案件包兼容证据通过；不同时双写两套库。 |
| 3. 根据基准优化 | 先看清洗、去重、DataFrame 物化和数据库写入；SQL／列式批量优先。减少全量复制，必要时再比较 Polars。 | 同一资金 oracle、两档以上规模和足够重复样本证明端到端收益，再决定是否增加依赖；不以语言偏好启动 Rust。 |
| 4. 完成独立工作区体验 | 迁移 G6 的实例生命周期与案件状态，补表格选中→图谱→来源流水、受控导出回读；采用 Analytix 设计 token，补键盘、长字段、多币种、失败恢复和任务进度验证。 | 每迁移一条任务就核对原始数据与可见结果；其余旧页保留，不一次重绘全站。 |
| 5. 接入 Analytix | 先用 fake host 明确 capability/version、workspace/case/snapshot、取消／幂等、权限撤销及结果投影；随后在单独授权的 Analytix 工作中补足 native authority，再挂现有工作区侧栏。 | 真实 Host 准入与可见 UI 分别验证；精确显示走 Core，复用已有 Go Harness／Funds／Rust data-engine；不绕过当前不可用状态。 |

命名不再反复变更：产品 **FundsTrace**、源码目录／未来仓库 `funds-trace`、Analytix 入口建议 **资金追踪**，具体位置优先放在案件项目已有数据分析导航里，复用当前工作区而非再选一遍案件。文件继续按职责分类：Python `snake_case.py`、React 组件 `PascalCase.tsx`、工具 `kebab-case.ts`、行为回归 `test_<behavior>.py`、文档 `kebab-case.md`；不批量创建空模块或把生成文件混入源码。

治理先保持小而可靠：`AGENTS.md` 只保留适用范围、真实命令、数据红线与验证；长研究放文档。后续拥有可核验 Git 历史和来源授权后，再建立小 PR、契约漂移／回归／构建 CI、依赖与资源许可清单、版本及兼容说明。性能测试采用单独可复现作业，不把普通 CI 的共享机器计时当回归阈值；公开样例、截图和日志只用合成材料。开源许可与发行另定，不从参考仓库复制许可结论。
