# 图谱首屏、布局与增量展开研究计划

日期：2026-10-16。本文记录源码现状、论文依据、本轮验证与后续分批目标。
范围：维护源码中的 G6 图谱；只使用合成数据，保留现有顶栏与画布面积，不做正式打包。

后续 P0 的一手资料、结构决策、规模／可读性边界与施工顺序见 [图谱首屏展示 P0](graph-first-screen-p0.md)。本页保留前几轮研究及其候选证据，旧计时不能代替新候选验收。

## 本轮边界与状态

- 延续已选样式：简单图上下支路统一向屏幕右侧拱起，水平关系文字上置。
- 复杂图文字固定在所属路径中段留缝，选中描边也留缝；允许交叉处遮挡，不漂移文字归属。
- 节点与关系标签均为纯文字，无底色、边框或引导线；真实 source/target、金额和来源不变。
- 本轮已实现并定向验证：默认文字 `fontSize=13`、`lineHeight=18`，保留用户已保存的显式设置。
- 本轮已实现并定向验证：按画布内真实可用空矩形适配相机，缩放上限 `1.6`，考虑图例、概览等覆盖区域。
- 本轮已实现并定向验证：最多 80 节点的 force 纳入节点与文字尺寸、边标签宽度，允许超出初始世界矩形，再做有限防重叠；更大图保留原有路径。
- fit 测量前移除上轮屏幕空间的临时文字避让偏移，以原位文字几何计算相机，再按新倍率避让，避免连续 fit 的倍率漂移。
- 已有保存坐标的画布仅做相机适配，不因打开、调整文字或“适应画布”自动重排。
- 三阶段核心已实现：稳定追加、SCC 资金流向分层、拓扑分区与局部布局；默认新画布为智能布局，旧快照合法布局值继续保留。
- 这是结合现有 G6 的几何实现，不声称完整复刻 Dagre、ELK 或论文算法；成员折叠、业务社区识别与独立固定位置操作仍未引入。

## 施工前源码事实与本轮处理

主要入口是 [app.js](../static/app.js)、[graph-layout.js](../static/graph-layout.js)、[graph-labels.js](../static/graph-labels.js) 与 [graph-viewport.js](../static/graph-viewport.js)。

| 本轮前的实现事实 | 影响与解释 |
| --- | --- |
| 自研 force 通常运行 110 轮，较大图有不同轮数和近似计算路径 | 固定轮数不是收敛质量或交叉数量的保证。 |
| 坐标硬夹在 viewport 内，未完整计入节点及文字尺寸 | 节点中心分开仍可能文字重叠；为塞入同一矩形，边缘易拥挤。 |
| `structural` 使用 BFS 距离安排同心环 | 是结构锚点，不表示真实时间、资金角色或完整资金流向。 |
| 原 `kind='dagre'` 是自研简化拓扑分层 | 已改为 SCC 凝聚、层级计算和重心扫层；仍不是上游 Dagre 的完整实现。 |
| 原追加采用邻居附近的 hash 播种，随后可能 auto fit | 已改为旧点固定、外围候选评分，并移除普通、批量、表格勾选三个自动 fit 入口。 |

首轮解决尺寸与相机问题；随后本轮落实三阶段核心，验证仍按功能分别记录。
节点位置、连线路由、文字位置、相机变换分别负责不同问题，需保持明确接口。
`fit` 只移动和缩放视图；`relayout` 才改变坐标；追加节点应有独立的局部放置策略。

## 应如何选择布局

节点数只是成本提示，不能作为唯一选择条件；11 个节点的密集循环可能比数十个叶节点更难阅读。
先计算连通分量、边数、度数分布、叶节点比例、链路深度、强连通分量（SCC）及回流关系。
再结合标签实际宽高、照片/强调节点尺寸、当前视口比例和当前选中追踪锚点决定布局。
稳定排序与固定种子用于复现；无业务依据的金额、身份或角色排序不得伪装成分析结论。

| 图结构或任务 | 建议布局 | 需要防范的情况 |
| --- | --- | --- |
| 少量账户、清楚主链及上下支路 | 水平主链、支路通道与统一右弧 | 主链需由拓扑与显式追踪目标确定，不能改箭头迎合形状。 |
| 汇入、流出、长链追踪 | 资金流向分层 | 循环和跨层边需独立路由，强行单向会误导。 |
| 以一户查看邻域、扇出较多 | 中心径向或分层扇区 | 高度节点需更大半径与展开预算，不能挤成一圈。 |
| 多个独立团块 | 分量各自布局后打包 | 小分量不能漂到远处，把全图适配比例拖得过小。 |
| 密集循环、社区之间少量连接 | 分区概览及局部网状布局 | 分区不等于业务团伙；折叠须明确数量、关系与展开入口。 |

首屏目标是让结构可辨、文字可读、边界完整，并合理利用可用画布；不以填满每一处空白为目标。
“全部显示”与“所有文字保持可读”在大图中可能冲突，应提供概览、局部定位和明确的显示范围。
不能为获得干净截图默默删账户、隐藏金额，或将复杂图文字从所属路径中段移走。
建议后续增加屏幕字号验收目标（例如关注区域不少于 12 屏幕像素，具体值经实测确定）；世界字号 13 在 0.5 倍视图里只有约 6.5 屏幕像素，单改字体默认值不能解决这种缩放冲突。
首布局需结合视口长宽比控制主链间距和支路通道；保留坐标的画布不能为填空白而在 fit 时偷偷压缩某个轴。

## 阶段 1：稳定的增量展开（核心已实现）

1. 以展开操作开始时的旧坐标和相机为基准，记录新增节点、已有节点、新增边及操作来源。
2. 旧节点坐标硬固定，追加时以实时手拖几何为准；普通重画则尊重对齐、均布和历史指定坐标。隐藏账户的已保存节点与文字占位也保留。
3. 从展开锚点的外围扇区和外圈生成确定性的候选位置；旧点达到三个时保守保护整个旧图包络，不在内部找空洞。
4. 候选评分包含节点/文字碰撞、旧边穿越、增加交叉、距离过远及偏离追踪方向的代价。
5. 对新分量优先在现有图谱外围放置，独立打包；同一账户已存在时复用旧节点。
6. 初次候选不足时扩大搜索半径或增加局部空间，不把新增节点塞入原有交织区域。
7. 只给新点分配位置，沿用现有边路由与中段文字渲染；输入含旧弧线/人工路径采样、实际文字包络，不只看端点直线。
8. 追加保留完整相机矩阵。已有“查找定位”弹层内提供“定位新增”，由用户主动平移，倍率不变；“适应画布”仍是主动全图缩放入口。
9. 新增超过 32、显示节点超过 500 或新旧关系超过 800 时，采用总障碍包络外的排架，跳过候选交叉评分；旧路径取实际包络而非逐段采样。阈值是工作预算，不是计时性能承诺。

本阶段优先获得可预测的展开行为。若未来允许旧邻域小幅移动，必须作为显式选项，并另设位移上限。
节点、文字与路径索引需随拖动和折点编辑失效更新，不能使用过期碰撞数据。

## 阶段 2：资金流向分层（节点层级与排序已实现）

- SCC 缩点形成布局用 DAG，保留全部原始关系，循环内部再布局；不得重写业务方向。
- 使用迭代 SCC 凝聚、DAG 层级和双向重心扫描，保留交叉指标最好的层内顺序，再按完整文字尺寸分配坐标。
- 凝聚边不超过 600 时比较实际 block-edge 直线交叉，以上使用邻层逆序指标；这不是任意 G6 曲线交叉最少的保证。
- 长边、回流、双向边及自环继续由既有渲染路由负责；独立的外侧长边通道和 dummy-node 路由尚未引入，不把节点层级改进等同完整边路由优化。
- 优先评估已 vendor 的 G6 4.8.19 布局能力和当前接口，核对具体版本后复用，不默认增加依赖。
- G6 继续负责交互和渲染，布局只输出几何；金额字符串、账户 ID 与来源不进入数值化转换。
- 全局重排保留人工折点坐标及标签沿线比例，沿用可撤销历史；极端重排后人工路径可能需要用户重新整理，不静默清除。

## 阶段 3：复杂图分区（几何分区已实现，中心探索继续沿用邻域）

- 先做连通分量、桥连接结构块和有预算的邻域切分，每区使用局部布局，再按最终完整文字包络排列；不删除或折叠成员。
- 默认智能布局先识别简单主链与支路；高扇出、密集图和过长主链转分区处理。保留“主叶铺开”和“力导向”供主动选择。
- 简单主链的水平文字有独立上置文字带，步距取节点占位、边标签宽度和支路宽度需求的最大值，避免重复相加；多行支路另计标签高度和节点文字偏移。
- 分区只表示拓扑几何；不新增业务团伙标签。中心径向的入/出扇区、折叠概览与金额口径属于后续功能，当前沿用已有邻域/聚焦入口。
- 同一主体、银行或账号合并涉及身份与统计契约，不是布局功能，不在本阶段擅自实施。
- 根据实际测量决定 Worker、粗化与预算，不能引用论文节点数承诺本机性能。

## 建议补充的操作与共通契约

- **固定位置**：锁定手工整理结果；全局重排明确提示约束是否可满足。
- **定位新增**：定位本次展开区域，保留旧倍率，并可回到原追踪锚点。
- **展开预算**：按层数、方向、笔数或账户数渐进展开，显示尚未展开的数量及当前范围。
- **来源/去向**：分开上游与下游探索，保留交易原始方向、币种和精确金额。
- **撤回本次展开**：作为一个有边界的历史操作，只撤回本批新增显示成员；失败不能报撤销成功。
- 布局任务可取消；新任务、切换案件/画布或关闭视图后，旧 Worker/异步结果不得覆盖新状态。
- 保存节点坐标、相机、显示设置及人工折点；保存、重开、历史恢复和 PNG/PDF/HTML 导出保持同一几何语义。
- 视图筛选、折叠与标签范围不修改完整追踪事实；导出声明当前视图和文字显示范围。
- 沿用 [图谱交互](graph-interaction.md)、[视口](graph-viewport.md) 与 [工作区](graph-workspace-plan.md) 的案件绑定及面积约束。

## 首轮尺寸与 fit 验证记录

- 维护源码的六组定向 Python 入口共 `69 passed`，覆盖布局内核、图谱交互、标签呈现、历史、顶栏命令及导出；其中 Python 入口调用对应 Node harness。另有旧导航 harness 的直接检查，不把重复运行计为独立用例。
- 浏览器使用独立合成预览，11 个账户、10 条关系。原标签画布与原用户标签页保留，另存自动布局测试画布。
- 同一组坐标、同一 `679 × 573` 画布，最终 fit 的倍率从 `0.6748` 提升到 `0.7311`，显示尺寸约增加 `8.35%`；没有重排坐标。中间候选曾测得 `0.8936`，但包含尚未修正的临时文字偏移，不作为最终提升数字。
- 修复临时文字偏移后，另存的自动力导向画布连续 fit 倍率约为 `0.9534`；后两次相机矩阵最大差约 `1.9e-12`，节点坐标保持一致。此结果对应该合成图，不承诺所有图相同倍率。
- 实际浏览器检查简单图的统一右弧、水平上置文字，以及复杂图中段文字留缝、纯文字样式；自动 force 仍可能产生边交叉和关系文字遮挡，不把尺寸改善宣称为消交织已完成。
- 实际通过界面另存并重开自动布局画布，导出 HTML 文件检查到 11 节点、10 关系、13/18 文字样式、原始方向及精确金额字符串；这项只证明导出内容，不代替离线 HTML 交互或 Windows 导出验收。
- 没有做正式打包、Windows GUI/DPI 验收或计时性能验收。超小容器、覆盖层占满内框、或全图需要低于现有 `0.02` 最小倍率时，完整无遮挡适配仍有边界。

## 一手研究依据及适用边界

1. [North、Woodhull：On-line Hierarchical Graph Drawing](https://graphviz.org/documentation/NW01.pdf)：增量分层、旧位置/固定约束与局部交叉优化；稳定与可读性存在取舍。
2. [Gansner、Koren、North：Graph Drawing by Stress Majorization](https://graphviz.org/documentation/GKN04.pdf)：以图距离优化几何距离；stress 较低不等于文字无重叠或交叉最少。
3. [WebCola 作者官网](https://ialab.it.monash.edu/webcola/)：间距/对齐/防 bbox 重叠，先解缠再施加约束；官网也说明大图扩展性有限。
4. [ELK Layered 官方算法](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)：分层、交叉排序、坐标和路由分阶段，支持边标签及多重边。
5. [ELK：Constraining the Model](https://eclipse.dev/elk/blog/posts/2023/23-01-09-constraining-the-model.html)：旧位置与交互排序约束；具体选项受版本和调用方约束执行方式影响。
6. [elkjs 官方 GitHub](https://github.com/kieler/elkjs)：JS 布局与 Worker 接口参考，是未来候选，不是本轮已引入依赖。
7. [Yifan Hu：Efficient and High Quality Force-Directed Graph Drawing](https://yifanhu.net/PUB/graph_draw_small.pdf)：多级粗化、细化与 Barnes–Hut 近似力；不自动解决首屏可读性和增量稳定。
8. [Archambault、Munzner、Auber：Grouse](https://www.cs.ubc.ca/labs/imager/tr/2007/Archambault_Grouse_EuroVis/grouseEvis.pdf)：按拓扑选局部算法，渐进展开与有限重排；大幅尺寸变化仍可能打破稳定性。
9. [G6 4.8.19 布局注册源码](https://github.com/antvis/G6/blob/4.8.19/packages/pc/src/layout/index.ts)：该版本注册 force、dagre、radial、concentric、forceAtlas2 等；是否可复用须核对现有 Worker、配置和路由适配，存在注册项不等于当前产品已经调用。
10. [Dagre 官方 Wiki](https://github.com/dagrejs/dagre/wiki)：节点尺寸、rankdir、nodesep/ranksep 与边标签尺寸是布局输入，适合评估真实的有向分层能力。
11. [fCoSE 官方 GitHub](https://github.com/iVis-at-Bilkent/cytoscape.js-fcose)：固定、对齐和相对位置约束的实现参考；它是 Cytoscape 扩展，不是可直接替换本项目 G6 的插件。

以上是研究依据。各阶段的具体评分、阈值与界面选择是 FundsTrace 的工程建议，须经合成验收和实际测量后收敛。

## 交互可靠性收敛：先限制写入权，再增加布局能力

当前微拖回跳的真实触发为：自定义手势已跨 4 CSS px，而 G6 仍在 mouseup 中发出 click；选择处理先取消手势，再到全局 mouseup，因此回滚并打开详情。标签跑偏来自节点碰撞候选会更换锚点。这两个问题不能通过换一个布局算法消除。

工程边界固定为：

| 对象 | 允许的写入与优先级 | 禁止的副作用 |
| --- | --- | --- |
| 节点坐标 | 首布局、显式重新布局、手动拖动、历史恢复、读取已存坐标；追加只分配新点 | hover、标签 LOD、Fit 不得改节点坐标；旧 Worker 不得迟到覆盖拖动 |
| 节点文字 | 同一共享函数按真实主体／字形包络，居中下置、6 CSS px；auto／focus 只裁可见集合 | 不得绕到顶部或侧面，不生成底板、边框或引导线 |
| 关系文字 | 原路径中段；简单水平关系上置；复杂关系中段留缝 | 不以避让改变所属路径或原始资金箭头 |
| 手势 | 阈值前点击；阈值后完整拖动且只结算一次；明确取消恢复原位 | 已开始拖动不得被 G6 提前 click 取消；离窗／失焦不得悄然回滚 |
| 相机 | Fit 在一次命令内确定最终 LOD 和固定屏幕间距的包络，再求缩放与居中 | 不能把前次缩放的临时字框当成最终尺寸；重复 Fit 不得逐次漂移 |
| 保存与输出 | 保存语义坐标／样式，读取和导出共用文字锚点；采样后恢复相机及选择 | 不持久化自动避让的侧偏移，不把导出采样比例带回交互画布 |

验收从独立函数扩展为用户操作序列：点击／微拖 → 松开 → hover → zoom → Fit 两次 → 追加 → undo／redo → 保存重开／导出。断言坐标、相机、实际文字包络和历史数量；覆盖真实 G6 事件次序、丢失 mouseup、失焦／离窗、50 节点预览、旧绑定及长文字。单测绿只证明其覆盖的契约，合成浏览器与实际 Windows／DPI 证据分别记录。

[elkjs 官方说明](https://github.com/kieler/elkjs)明确其负责位置计算，不负责渲染和样式；[D3 simulation](https://d3js.org/d3-force/simulation)提供停止计算与 fx／fy 固定位置；[G6 4.8.19 drag-node](https://github.com/antvis/G6/blob/4.8.19/packages/pc/src/behavior/drag-node.ts)也单独处理手势终态。[DynaDAG](https://graphviz.org/documentation/NW01.pdf)讨论增量图中保持稳定和改善布局的取舍。这些是一手实现参考，不构成替换当前 G6 的理由。本阶段停止增加新布局，先确保所有现有算法遵守同一组交互契约；无法承诺零缺陷，也不以堆叠算法数量替代验收。
