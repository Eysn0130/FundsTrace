# 整包来源绑定与正确性续修

本文保留来源绑定、撤回与内部成本修复的维护要点，以及已执行检查的边界。任务 1–28 的逐轮计划、首次失败、修正与测量原态可在[固定历史正文](https://github.com/Eysn0130/FundsTrace/blob/d158cffdc0017cf2371a02c0e3d87ff207ca4611/docs/import-closure-delivery.md)回查；其中旧 Draft、未合并和下一步计划只描述当时状态。历史检查不因代码进入后续主线而成为新候选的验收。

## 行为和实现

- 来源位置及操作范围的少量派生字段保存在操作专属 SQLite 的窄覆盖中，读取时还原完整对象；覆盖只允许闭合的字符串字段，损坏拒绝读取。普通晚修改仍写回完整有效记录并消耗覆盖，旧引用、明确删除、重绑定、取消及稀疏来源位置保持原语义。打包备注只读取一次；预览样本沿既有索引和分类选择器保持来源顺序与上限。
- 所有托管导入在成功回执的同一事务内保存独立操作关联。撤回先移除本次支持；仍有有效来源链接和操作支持的流水保留 ID、原字段及图上引用，最后支持消失才删事实。来源元数据本身不是支持。历史资料只按可核验的关联迁移，不猜补或复活已丢流水，见[来源与撤回](import-lifecycle.md#从流水回到来源)。
- 纯解析复用只保留当前进程的一份完整计划，最长 60 秒。案件绑定的临时工作索引与纯计划文件分开，两个文件共享原 8 GiB 暂存额度，结束即清理；真实计划变化仍写回原 store。完整文件／有效元数据摘要、原件核验、缓存键、唯一所有权和事务内案件重验保持，缺失或到期重算、损坏拒绝。缓存不是可恢复业务状态或写入授权，详见[有限的纯解析结果复用](import-lifecycle.md#有限的纯解析结果复用)。
- 暂存去重索引的小摘要只筛选候选，命中后仍解压并逐字节比较完整身份；来源范围、稳定流水选择及批内 pending 去重不变。items 使用普通 rowid 表并显式保留复合键的非空与唯一约束；rowid 不进入业务 ID、来源顺序或导出。该布局的保留理由是实测空间减少，未证明稳定提速或内存改善。
- 同一表头区域只复用有序、不可变的表头文字及 28 列识别结果；新区域、工作表、成员、profile 和重新预览重新建立。金融单元格、角色、引用、来源位置及校验仍逐行判定。身份文本快路径保留原类型／Unicode 拒绝规则；一次重建只复用最多 128 个完整成功验证的原文，每项最多 8192 UTF-8 字节、保留原文预算最多 1 MiB，每遍仍生成独立对象并在退出时显式清空。父子反向索引只替代直接关系查找，不取递归闭包或跳过冲突判断。
- 分页请求共享选定观察与资金汇总；已声明唯一来源的观察页先选窄页键，再取当前页完整字段。来源过滤、去重、排序、全范围金额／未知值和修订同属一份有效读快照，保留 DuckDB 窗口规划的物化边界。通用来源保留其内部一致的单次选择路径；不增加跨请求缓存或全案 Python ID 集合。

当前上传选择条件和保存版本统一见[自动导入](automatic-import.md#新上传解析版本)，来源、身份及事件语义见[文件夹来源证据](folder-evidence-import.md)，金额／时间见[金额契约](money-contract.md)。案件包导出优先级、格式 1–7 兼容与不含原始上传字节的限制见[案件包格式与兼容](import-lifecycle.md#案件包格式与兼容)；不能把本记录曾引入的格式 6 或 archive-v8 写成当前默认。
