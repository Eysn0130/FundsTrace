# 整包来源绑定与正确性续修

本轮从 `dffb2764224148a8cfd5285e6c8cc13a794fa9be` 开始，堆叠在 Draft PR #83 上，继续依赖 #82/#81。当前仅形成可审查候选；99 整包及总体目标尚未通过，未合并、正式打包或发布。

## 行为和实现

整包预览为来源位置和来源范围增加少量派生字段时，原实现会重新压缩、写回整条流水与来源记录。现在只在操作专属 SQLite 暂存中写入这些字段，读取时还原完整对象。普通后续修改仍写回完整有效记录并消耗增量覆盖；旧引用、明确删除、重新绑定、取消记录及稀疏来源位置保持原语义。前两切片关闭操作即释放暂存；第五切片增加下述有限的纯解析结果复用，仍不增加可恢复的业务状态。

打包备注在序列化时只读取一次，避免通过 Mapping 为每个字段反复读取同一备注。预览来源样本使用既有来源编号索引；前十项未决示例使用已有分类选择器，保持来源顺序与上限。

前两切片只修改暂存；本轮后续增加独立操作关联和 `.fundcase` 格式 6（见后文）。原件、来源位置、Decimal 金额、微秒、身份/事件判定规则及 API 形状保持原契约。暂存覆盖只允许闭合的字符串字段，损坏覆盖拒绝读取；失败不能留下已提交的部分案件。

## 第五切片：纯解析复用与整链成本（任务11）

运行时的整包来源位置绑定同时补齐无机构声明的操作范围，完整字段与旧完整解码路径等价；后续改动仍经过既有重验。整包统计在已完成成员进入暂存前累加，避免重新读取全部暂存求相同统计。纯解析结果可以由当前进程保留一份、最长60秒；只有案件绑定前后完整暂存文件与解析元数据摘要完全相同才合格。提交仍校验注册原件和缓存完整性，并在原子写入事务内重新做当前案件校验。配置、案件、surface或任务不匹配不得复用；缺失时重算，损坏时拒绝。详见[生命周期与强制退出限制](import-lifecycle.md#有限的纯解析结果复用)。
