# 整包来源绑定与正确性续修

本轮从 `dffb2764224148a8cfd5285e6c8cc13a794fa9be` 开始，堆叠在 Draft PR #83 上，继续依赖 #82/#81。当前仅形成可审查候选；99 整包及总体目标尚未通过，未合并、正式打包或发布。

## 行为和实现

整包预览为来源位置和来源范围增加少量派生字段时，原实现会重新压缩、写回整条流水与来源记录。现在只在操作专属 SQLite 暂存中写入这些字段，读取时还原完整对象。普通后续修改仍写回完整有效记录并消耗增量覆盖；旧引用、明确删除、重新绑定、取消记录及稀疏来源位置保持原语义。关闭操作即释放暂存，不增加可恢复的业务状态。

打包备注在序列化时只读取一次，避免通过 Mapping 为每个字段反复读取同一备注。预览来源样本使用既有来源编号索引；前十项未决示例使用已有分类选择器，保持来源顺序与上限。

没有改变原件、来源位置、Decimal 金额、微秒、身份/事件判定规则、持久数据库 schema、API 形状或 `.fundcase` 格式。暂存覆盖只允许闭合的字符串字段，损坏覆盖拒绝读取；失败不能留下已提交的部分案件。

## 批次撤回修复

删除一个导入批次先撤回该次操作的支持。仍有有效来源链接及有效来源—批次关系的流水保持ID、原字段和图上引用，存储归属改至剩余批次；最后支持消失才删除事实。来源元数据本身不算支持，历史回执和原文件保留。旧无明确操作关系的非evidence来源维持原删除行为，不猜补或复活历史事实；详细兼容含义见[导入生命周期](import-lifecycle.md)。

新增公共反例在修复前3失败/1通过；确认文案14通过/1失败。修复后覆盖两种删除顺序、三份支持、混合独有/共享流水、跨案拒绝、事件/卡账回退、图上引用、修订与旧导出拒绝、包往返、原子回滚。既有测试中“删除最初批次即删除所有副本”的预期按既定最后支持契约更新，保留旧失败；不更改真实gold。后续定向158项中仅一项旧增量预期失败，修正后相关22项通过；确认文案及异步交互15项通过。最终稳定候选全套4610项及108子测试通过（502.53秒，1条测试依赖弃用警告）；API契约、G6固定hash与diff检查通过。

真实补验运行器的首轮httpx响应管理用法错误和第二轮撤回产品失败均留存；另一次新测试仅因API字符串ID与数据库整数ID比较失败，已显式统一ID类型。失败没有计入通过分母。


最终撤回候选的小链10例、3完整请求闭包均重新通过。小链逐案读取核对合计12,738条观察，487条追踪观察完成图/Excel核对；邻居核对6例适用、4例不适用。闭包逐案合计8,627条观察、300条追踪观察。不同案例可能覆盖相同原件，这些数不代表互不重叠的真实交易总数。剩余5组两种删除顺序各完成2完整请求、48次公共请求，目标12条原观察全部保真且最后支持撤回成立。真实经济事件确认正例仍为0。
