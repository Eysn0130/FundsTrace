# 布局切换与重新布局性能优化

日期：2026-10-16。维护源码在 funds-trace；全部测量使用独立合成预览、冻结静态资源和临时数据库。未连接原业务实例，未增加布局引擎、Rust/Wasm 依赖，未打包。

后续的跨规模结构边界、响应性风险及分批施工方案见 [韧性复核](graph-layout-resilience.md)。以下数据继续对应本轮冻结性能候选，不因后续防护或研究而重新解释为新测量。

后续三批施工的新候选与测量见 [布局管线交付](graph-layout-pipeline.md)，不与以下历史数字拼接计算加速倍数。

## 结论与计时口径

本轮主要瓶颈是 Worker 完成后反复处理 G6 几何、标签和绘制。首先减少等价重复工作，保留迭代次数、全部文字、五种布局和实际曲线路由质量门禁。没有通过关闭留缝、隐藏关系或少跑布局迭代取得速度。

环境为 Apple M4 Pro、macOS 26.5.2、本地 Codex 内置浏览器，固定 1280×720 CSS 视口、755×516 实际画布，查询区与功能区保留。计时从真实控件事件捕获开始，直到布局结束、历史不忙及后续两次 requestAnimationFrame；这是浏览器操作完成／帧回执，不能等同显示器物理呈现时间。测试工具调用和网络控制往返不计入时长。各阶段时间含嵌套调用，不能直接相加。独占计时期间没有测试、构建或其他性能采样任务并行。

1000 节点／990 关系、资金流向分层，各 30 次预热后的重复操作：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 操作完成中位数 | 855.35 ms | 398.10 ms |
| P95，nearest rank | 988.20 ms | 419.20 ms |
| 样本中的最长主线程长任务 | 808 ms | 313 ms |
| 每次应用显式请求绘制次数 | 2 | 1 |

该组中位数约 **2.15 倍加速、等待减少 53.5%**。最长任务仍超过 50ms，不能称为大图完全不卡顿。不是 Windows GUI／DPI 或其他硬件的性能承诺，未给冷启动／首屏加载建立分布。

## 实施内容与正确性边界

1. **保持批次绘制所有权。** Fit、标签刷新和视口裁剪恢复进入前的 autoPaint 状态，不在外层布局尚未结束时提前打开自动绘制。最外层统一提交一次画面；真实 G6 4.8.19 的 autoPaint 与 Canvas autoDraw 同时受此控制。关闭绘制仍有形状更新成本，因此继续减少无效更新。
2. **质量测量只收集需要的数据。** 规划阶段仍保留原 24 段采样；后续实际质量评估直接收集真实路径和文字，避免先做一份用不到的规划器输入，再由评估器采样一次。
3. **逐条补救只重测变化边。** 同步、相机不变的补救循环复用节点与未变化的边，当前边重新读取实际 G6 路径及文字。路径数组复制，避免 G6 原地更新污染缓存。最终仍进行新鲜的全图实测，保留最多 12 个试探和原七项全不退步条件；实际全场景收集由最坏约 15 次减至约 4 次，验收次数和预算语义不减少。
4. **标签稳定时不重复施工。** 初始仍完整放置与实测；仅对标签创建、成员／可见性变化和实际改样式的边追加处理。没有几何变化时复用第一轮避让结果；新字形出现时仍执行第二轮实测。最终每个可见标签只向裁剪索引补入一次。特别覆盖 G6 临时隐藏 text-shape 后恢复：即使成员与文本没有变化，仍恢复中段留缝。
5. **幂等图元适配。** 相同属性不重复写入；边缓存校验路径值、锚点、样式、文本与矩阵、可见性、clip、图元身份及字体加载代次。任一不一致重新计算。节点不缓存位置，每次校验实际屏幕包络与 6 CSS px 间距。缓存属于 WeakMap 图元生命周期，不进入历史／保存格式。
6. **等价空间索引。** 查询使用访问戳减少临时 Map、Set 和数组；交叉角度延迟到确实保留 witness 时计算。保持遍历顺序、预算 checks、witness 顺序与确定性结果。

没有增加长期跨图谱布局缓存，没有复用旧案件异步结果，没有改变金额／方向、人工折点、追加策略、Fit 所有权或 G6 版本。

## 验证

- 最终候选的 21 个定向 Python 测试文件共 **95 项通过**，包括内部 Node 回归。计数有包含关系。
- 两个纯内核与冻结基线作 **1161 项完整输出 deepEqual**，覆盖 routes、stats、七项计数、witness、coverage、部分预算、反向、自环、宽范围和动态索引更新；结果一致。
- 新增幂等、外部改写、字体、图元替换与隐藏恢复回归；实际逐条验收的每个缓存输入与新鲜全图逐字段比较，覆盖接受一条后另一条与其相撞的反例。
- **25 组真实浏览器对拍**：节点坐标及控制点差为零；方向、金额、线型、颜色、留缝和最终遮挡计数相同。节点文字屏幕包围盒最大差约 1.14e-13 CSS px，属于浮点误差。
- 真实 7×3 CSS px 微拖动、其他节点固定、重复 Fit、撤销重做、自动／全部标签切换通过；复杂图 47 条标签均保留留缝、节点下置间距为 6 CSS px。
- 保存／导出格式没有变更，相关回归通过。真实浏览器保存后重开，节点及控制点一致；HTML 导出中的节点、控制点、方向、标签及精确金额与画布一致。PNG 导出完成后，节点、控制点和相机矩阵恢复一致，图像为 3020×2064。当前改动影响共享离线标签适配器，保留离线 HTML 全部风格回归；本轮没有额外将离线 HTML 在独立浏览器中重新打开作目视验收。对应回执在 final-export-verification.json。
- 静态资源同时绑定冻结候选指纹；性能脚本只位于独立合成预览，生产入口不加载。原始 JSON、冻结资源、对拍和命令输出保存在本任务 layout-speed 证据目录。

## 官方实现研究与 Rust 决策

Exa 进行了 4 次搜索、20 个结果位，并核读 8 个官方全文来源；结果位不是 20 份经过全文验证的论文。不使用通用语言速度排行榜推断本项目收益。

| 已核读依据 | 事实与本项目取舍 |
| --- | --- |
| [Chrome 长任务说明](https://web.dev/articles/optimize-long-tasks) | 超过 50ms 的任务会阻塞交互。拆函数不等于真正让出主线程。本轮降低重复工作，仍如实记录大图残余长任务。 |
| [MDN Worker](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers) | Worker 不直接操作 DOM，消息有复制成本。当前已有布局 Worker；把 G6 测量直接改成 Rust 或 Worker 不能自动省掉绘图工作。 |
| [MDN Transferable](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Transferable_objects) | 转移 ArrayBuffer 会分离原缓冲。未来大批几何传输可使用独立 Float64Array，不能转移仍被历史／画布引用的内存；金额和账户 ID 不数值化。 |
| [G6 4.8.19 graph.ts](https://raw.githubusercontent.com/antvis/G6/4.8.19/packages/core/src/graph/graph.ts) | 核对 setAutoPaint 与 refreshPositions 的精确版本实现，支持本轮批次与坐标更新选择；未引用 G6 新版替代本地契约。 |
| [G6 4.8.19 item controller](https://raw.githubusercontent.com/antvis/G6/4.8.19/packages/core/src/graph/controller/item.ts) | 关闭绘制不消除形状更新和边刷新调度成本，所以要减少重复调用。 |
| [Rust-Wasm 接口设计示例](https://rustwasm.github.io/book/game-of-life/implementing.html) | 粗粒度批量接口、长期数值内存有利于减少往返；教程不构成当前浏览器速度承诺。 |
| [wasm-bindgen 数字切片](https://wasm-bindgen.github.io/wasm-bindgen/reference/types/number-slices.html) | 数字切片仍可能复制；不能把 TypedArray 或 Wasm 等同整个链路零复制。 |
| [web-sys](https://wasm-bindgen.github.io/wasm-bindgen/web-sys/index.html) | Rust 调用浏览器 API 仍经过绑定，G6 与浏览器的工作不会随换语言消失。 |

**本轮不引入 Rust。** 原瓶颈以 G6 几何、标签和重复提交为主，已取得端到端收益；重写这些调用方比更换语言更直接。剩余 1000 节点 force 的 Worker 约 0.33 秒，确实值得作为后续纯数值热点候选，不能因此推断全部布局都应迁移。

若目标硬件仍达不到交互要求，下一步有证据价值的方向是：先将剩余纯路由／碰撞计算后台化并绑定几何版本、减少专用数值缓冲传输；再对 force 的纯计算内核做隔离 Rust-Wasm 对照，计入初始化与复制成本，验证与 JS 的方向／几何／门禁及端到端 P95。最终 G6 提交继续原子、旧任务无权回写。未经这类实测，不承诺十倍加速，也不更换已经满意的布局效果。
