# 文件夹导入与来源证据关联

这条导入路径将流水、账户资料和子账户资料作为同一次案件操作处理。原件和原始流水留存，节点身份由可撤回、可重算的来源证据投影生成。内部实体 ID 不作为用户看到的银行卡号或账号。

## 入口与接纳范围

- 案件与导入页支持选择文件夹及拖入目录；旧画布导入框也提供文件夹选择。
- v1 入口是 `POST /api/v1/cases/{case_id}/imports/directory/preview`；legacy 入口是 `POST /api/import/directory/preview?case_id=…`。multipart 的 `files` 字段携带完整相对路径。
- 后续预览、提交、进度和回执复用原有案件绑定生命周期。文件夹只产生一个导入操作；提交流水、来源日志、辅助证据和关联版本在同一事务内完成。
- 新解释路径在写入前，将已校验的完整来源日志暂存到操作专属临时文件，逐遍校验记录数和内容摘要；写入、验证及身份重算按块读取。暂存文件在成功或失败后关闭，不替代保全原件，不放宽金额或来源一致性校验。
- 新目录归档在每条记录解释完成后即压缩暂存详情，整个操作共享有限的解码缓存，避免等待大成员读完后才释放其全部未压缩备注；后续来源绑定、冲正与历史冲突仍可更新这些详情，写库时恢复完整原 JSON。缓存有界不等于整个导入占用恒定内存，资金行、记录索引和压缩内容仍随数据量增长。
- 冲正关联先按精确来源位置缩小候选，再读取其详情和资金链接，避免按整个案件或文件产生无用组合。新写入数据在未提交事务内可能尚无可靠的行数估计，导入事务因此临时保留已声明的连接顺序；它持有既有数据库锁，在提交或回滚完成后恢复原查询设置。嵌套调用遵从外层事务策略，资金校验和冲正证明不减少。
- 持久证据重放按来源及原始行号分段排序、读取完整备注，保留原解码及去重顺序，避免一次查询缓冲整案备注。重放期间只保存端点的紧凑索引，随后按原顺序生成决策。决策快照沿用原规范 JSON 和版本哈希，以私有临时文件写出；关系投影分批写入时释放已消费的 Python 行，由数据库核对文件名、字节数及摘要后载入快照。在同一写事务中，已经存在的不可变关联版本复用其审计内容，当前关系投影仍重建。正常成功和异常路径在事务返回前清理本操作文件；进程强杀时命名临时文件可能遗留，不宣称已有跨平台崩溃清理保证。实体、端点关系和最终数据库字符串仍随案件规模增长，这不是全流程恒定内存承诺。
- 路径、展开大小、成员数量、嵌套深度和记录数量仍有界。目录路径当前解析已适配 CSV／文本、XLSX 和 ZIP；RAR 与旧 XLS 附件保留原件并明确记为覆盖缺口，单文件旧 XLS 入口的既有适配不等于目录已经支持它。已识别 Finder 元数据不产生资金记录。附件的一个登记条目不代表其内部只有一条交易。
- 成功处理意味着完成已声明范围的处理，不证明来源完整、任意银行格式都可解析，或未知内容的金额为零。
- 覆盖率统计先按原解释规则读取来源详情，计算每条记录的冲突候选和版本优先级，再关联历史处置、按物理来源去重与窗口排序。完整备注不进入这组历史关联与排序；原始详情、表头修正证明、历史冲突、版本优先级和未知处置规则不变。

新解释版本分别为 `funds-trace-table-v20`、`funds-trace-table-archive-v6` 和 `funds-trace-bank-feedback-v6`。v19 / archive-v5 的既有证据继续按旧契约读取，不追写事件或记账顺序声明。普通 ZIP 只有存在可验证的来源清单绑定，且含流水与账户／子账户角色资料时才自动启用新解释；目录入口显式使用新解释。其他旧入口和历史来源保留原版本语义；不得用新规则悄悄重写历史回执。检测到同一物理资金原件已有不兼容历史解释时，新路径明确拒绝混入，提示在新案件导入完整资料。先导入无明确来源范围的流水、后补清单并再次上传含原流水的整个目录，如果无法证明来源上下文安全衔接，也明确拒绝本次操作，保持原金额不变；单独补充辅助资料和原上下文稳定的重复上传另有回归。

## 数据层次

| 层次 | 用途 | 不作的推定 |
| --- | --- | --- |
| 原件及来源条目 | 保留文件字节、成员路径、行位置、解析版本和处置 | 文件哈希不证明同一账户或同一资金事件 |
| 原始流水 | 保留来源金额、币种、时间、方向、卡账原值 | 不用补全覆盖原字段 |
| 类型化声明 | 账户、卡号、子账户、请求与机构归属 | 同名、号码相似、余额近似不构成身份合并 |
| 实体及端点投影 | 为可证明的账户关系提供内部 ID 与展示号码 | 卡片、主账户、子账不是无条件等价类 |
| 图表及分析 | 使用同一有效流水和端点投影 | 双方账簿记录不自动成为一笔经济事件 |

`flows` 保留原事实；`effective_flows` 提供当前有效流水与实体端点，同时携带 `raw_*_account` 和 `*_display_account`。节点、检索与操作使用实体键，号码只负责展示和别名检索。`resolution_entities`、`resolved_endpoints` 和版本记录可从仍有效的来源声明重算。

## 关联规则

1. 明确的机构、标识类型和号码共同限定实体。不能因为案件内只出现过一个银行，就将无机构端点归给该银行。
2. 已适配反馈家族的请求清单、请求父目录和完整角色文件名可以共同声明来源范围。只能在同一逻辑来源家族内使用；文件名或任意目录名不能单独证明机构。
3. 同一明确账务账户关联多张卡时保留全部卡。展示号码采用稳定排序，不推定最新或当前有效卡。
4. 账号缺失时，仅在适用来源契约和唯一关系足以定位账务账户时关联。通用开户表中卡号与账号文本相同、未提供子账，不等于已经证明记账粒度。
5. 子账户保持独立账务实体和父子关系。不能按卡号、币种或“只有一个候选”随意选子账。
6. “账卡号”混合字段保留混合类型。只有明确机构范围下的唯一类型化关系才归一；冲突和无法判定者保留载体节点。
7. 新证据或批次删除会重新计算关系。晚来的矛盾必须撤回此前结论，不能以首次导入结果永久覆盖后续证据。
8. 户名出现多个来源值时保留这些值，不用 `MAX(name)` 冒充唯一真实户名。姓名不用于卡账身份合并。
9. 明确的缺失标记保留在原文件和来源证据中，解释为标识缺失，不成为卡号别名、机构归属或图节点。缺失对手标识的金融观察仍保留在流水中。全零值和字母数字标识不凭外观丢弃，也不使用 BIN 或长度推定身份。

字段角色也必须有来源契约。交易流水号和凭证号可以是两个独立编号，不能因为数值不同就当成同义字段冲突；已经适配的完整表结构分别解释这两个角色，保留原值及所选参考字段的依据。金额、方向、币种等真正同义字段的冲突仍拒绝接纳。新增一个参考字段契约，也不自动证明该文件的机构、账户或事件归属。

对于卡、账号都改变且没有明确接续声明的情况，相似交易只能提出候选，不能自动认定换卡。此版本不实现基于相似性强制合并。

交易行中的卡账共现与辅助开户声明也有区别：当前版本只把该行明确提供的卡、账号归入该行的实体，不将它自动复用为另一条缺账号流水的映射。仅观察到一个卡账组合，尚不能证明另一条流水适用的时间范围和记账层级；没有相应辅助声明时，缺账号行仍保留卡节点。这是“根据其他交易行补全关联”尚未覆盖的范围，不能将现有辅助资料关联能力表述为该愿景已全部实现。

## 重复与统计口径

同一可验证来源位置的重复上传可以复用原流水，并保留每次来源记录。目录排序或 ZIP 生成时间不应改变逻辑来源身份。不同机构或互相矛盾的来源解释不能仅因 CSV 字节相同而合并。

启用证据关联的案件，图和表统一按已接纳账务观察记录统计，币种分别汇总、金额使用 Decimal。缺少端点标识的已接纳记录继续留在流水表；画布只汇总已追踪且两端标识完整的记录，不能把两个不同范围的合计直接比较。图中的一条账户关系可以汇总多个来源记录，但记录数与金额不再通过时间邻近的 FIFO 镜像规则扣减。旧案件未启用该策略时仍使用历史显示规则。

这意味着 A 账簿与 B 账簿各出现一次的转账，尚未取得同笔事件证明时，保留两份观察。界面和导出明确标记这个口径，不能将观察金额合计称为去重后的实际资金量或结算净额。新事件层仅使用下述显式声明；节点归一不能替代事件证明。

## 事件与条件来源份额

table-v20 / archive-v6 只将同一行明确列出的 `参考号机构`、`参考号渠道`、`参考号业务域`、`跨账簿事件参考号` 作为事件作用域声明。通用流水号、凭证号、名称、同秒同额和近似余额均不替代这些字段。只有两份账簿的本方分别为付款及收款账户、双方账号机构明确、方向/币种/金额/时间一致且该参考组唯一时才关联；矛盾、重复使用和未解析的同组声明撤回关联。原分录和各自余额保持不变。图边另列已关联事件金额，未知/冲突记录不混入该金额。

`本笔交易后账面余额` / `交易后账面余额` 声明账面余额类型；`记账顺序号` 仅在同一来源、成员、表头区域、账务账户及币种内可比。不同文件、重复表头和上传顺序不构成可靠先后。明确余额和无透支约束只能在唯一可行顺序时用于排序；不能据此证明账本完整。

前后流水中的“条件来源份额”从本方入账选来源，按账户、币种及完整区间读取全部竞争分录，包含未上图分录。用户须分别声明区间完整、期初余额、无透支/授信和资金全额可用；这些声明不认证原件真实性。输出精确整数分计算的最小/最大可行份额、各自完整见证，以及独立 FIFO 规则份额。各目标上界不能相加；多账户通过已确认内部事件联合分配，按终止流出和期末留存核对本金，外部无回流是显式边界条件。

已知未解析资金记录、历史 `review`、冲正历史可用性缺口，以及同币种区间内无法排除的模糊本方分录会阻止计算。历史缺失/带符号金额不补造方向。单账户区间最多 100,000 条分录且见证单元最多 500,000；多账户最多 20 个账本、20,000 个事件，核计算另有工作预算。超界返回 `limited`，不截断后冒称完整结果。费用和普通退款只有作为独立本方资金分录接纳时才参与；不从余额差造账。

卡账及父子关系仍是静态来源声明：尚未实现有效期和历史换卡接续；冲正历史也未重建。真实资料缺少事件作用域、可靠顺序或完整账本证明时只能得到未知，不能将合成正例作为真实本金归属证明。实际验收与容量边界见[本候选记录](principal-attribution-delivery.md)。

## 生命周期与兼容性

- 关联结果有版本号；图、分析和导出带统计策略及关联版本。
- `analysis_revision` 在导入、撤回和案件包恢复的事务内更新。表、图、时间投影、上下文与分析共用该修订；本金导出必须带 `expected_revision`，当前界面的追踪表及图导出也发送修订。旧结果返回 409 并失效；工作簿“分析修订”页明确区分全案事件摘要和当前画布流水范围。旧图快照调用方可省略新增修订字段，但不能据此声称经过当前来源核验。
- 单次统计、流水页和追踪表导出在同一数据库锁内读取对应的资金、来源状态和关联版本。工作簿使用已捕获的端点资料生成，编码过程中不再查询当前关系，避免并发导入把旧流水与新版本拼在一起；只读取本次导出涉及的端点资料。
- 辅助资料或批次删除使实体 ID 改变后，画布通过前后共同追踪流水的同向端点迁移邻域、选择和账户过滤。只能唯一对应时保留原视角；身份范围无法唯一迁移，或隐藏节点合并会遮住原可见记录时，回到当前完整图。过期版本的本地草稿和命名画布不能恢复旧身份范围；保存的画布也不恢复旧交易事实。关联版本变化会使旧撤销记录失效，但不提前解锁正在执行的操作；追踪补偿只恢复追踪集合，不能恢复过期的关联结论。
- 主账号保留原标记声明，由当前明确的别名关系投影；冲突时不能将旧标记复制给多个账户。
- 身份对照和头像也保留原声明及原图。补充资料使卡实体归一到账户时，当前唯一的类型化关系可以投影这些资料；同一实体的证件值、照片原件或裁剪发生冲突时不任取一个。撤回关系后重新计算，不能沿历史已撤回的合并链继续传播资料。用户明确覆盖或清除当前账户资料时，处理其当前唯一关系覆盖的声明，避免编辑后旧值再次出现。
- 删除辅助资料批次也必须撤回对应证据，不能只删除有流水 ID 的记录。
- `.fundcase` 格式 5 携带新证据语义，导入后重建投影；旧格式继续按原规则校验。格式 5 不声称旧版本客户端能够理解。
- 失败不得遗留部分流水、部分证据或成功回执。切换案件后，迟到的上传、预览、候选或图响应不得进入新案件。

## 验证方法

公共回归位于 `tests/test_folder_evidence.py`，只使用合成资料；目录控件、宿主撤销、精确实体绑定和画布号码检索有对应前端与 legacy harness 检查。API 变更使用 `scripts/export_api_contract.py --check` 核对生成契约。

真实资料回放与公共测试分开：原件只在授权的本地私有临时目录中处理，独立读取器先冻结预期，再通过公共 API 比较当前主线与候选。逐记录核对原字段、金额和币种，核对导入顺序、重复上传、来源处置、节点依据及同范围图表统计。真实原件、身份、交易和第三方源码不得进入仓库。

性能比较须注明版本、相同输入、相同工作量、持久化范围、计时边界和串行采样环境。低层清洗函数、完整导入服务和原工具 GUI 不是相同工作量，不能直接按耗时排名。验证结果应另附实际执行记录，不能将本文的验收要求当作已经通过的证据。
