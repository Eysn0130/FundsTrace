# 合成数据性能基线

**本页数值是统一持久导入任务、来源追溯和上传生命周期改造前的历史基线，绑定下方源码指纹。当前候选已经改变，尚未重采三档计时，不能声称保持相同性能或按旧数值证明没有回归。** 历史 JSON 保留原貌，不覆盖成新候选证据。

基准入口是 `scripts/benchmark.py`，测量 Python 业务函数与 DuckDB SQL。数据由固定 seed 的整数规则生成；不连接现有数据库、业务服务或真实 Provider。CSV、临时数据库和 Excel 均随每个子进程的临时目录清理，JSON 只保存环境、策略、聚合校验与性能指标。

既有路径直接调用解析／清洗／`commit_rows`，没有测量本轮任务登记、请求冻结、来源关联、上传摘要快照、回执恢复、清理或 React 可见耗时。未来新基线需要同时扩展这些用例与相应正确性校验，再按相同环境采样；不能用函数级旧计时替代持久服务端到端结果。百万行合成 CSV 约 477MB，也超过当前 HTTP 上传 300MiB 限制，因此其记录仅是直接函数容量观察，不证明该文件可通过上传入口导入。

## 复现

以下命令可在候选根目录使用锁定环境重新采样；`candidate-*` 为新候选输出名，不能据此复现历史源码指纹。计时期间停止其他构建／测试／基准工作，先确认当前正确性检查通过：

```sh
.venv/bin/python scripts/test.py tests/test_benchmarks.py
.venv/bin/python scripts/benchmark.py --check --rows 100 --repeats 1 --output output/benchmarks/smoke.json
.venv/bin/python scripts/benchmark.py --rows 10000 --repeats 3 --output output/benchmarks/candidate-10k.json
.venv/bin/python scripts/benchmark.py --rows 100000 --repeats 3 --output output/benchmarks/candidate-100k.json
.venv/bin/python scripts/benchmark.py --rows 1000000 --repeats 1 --output output/benchmarks/candidate-capacity-1m.json
```

默认 10,000 行、3 次重复、seed `20261014`、DuckDB 2 线程。`--rows` 限 100～1,000,000；性能观察至少 10,000 行。`--check` 仅允许 100～1,000 行，结果标记为 `correctness-smoke`。`--repeats` 限 1～30，`--threads` 限 1～8，`--seed` 限 0～2,147,483,647。`--graph-rows` 最多 2,000，`--excel-rows` 最多 10,000；实际样本数同时受有效唯一流水数限制。完整性失败或运行期间源码变化时退出非零，不用部分成功结果生成新报告。

每个完整重复单独启动 Python 子进程并创建全新 `TemporaryDirectory`，在导入应用前强制覆盖 `FUND_DATA_DIR`、`MPLCONFIGDIR` 和公开标注的合成授权配置。初始化还要求目标数据库尚不存在。继承路径隔离回归把旧路径指向含不可打开数据库哨兵的目录，确认该目录、授权哨兵及继承的 Matplotlib 路径未被修改。导入业务模块的字节码缓存前缀也位于本次临时目录，避免复用应用的旧字节码。

## 数据与校验

CSV 有 21 列，包含中文、8 个额外宽字段、可空银行/余额/币种/摘要、日期斜线与货币符号格式、前导零账号、256 个对手账户、收支方向。每 100 行有 1 行无效日期和 1 行无效金额，每 10 行的第 10 行重复前一行。另有 1 笔 `9007199254740991.13` 的大金额哨兵，用来检出金额经 binary64 中转丢失分的问题。

预期行数、去重数、金额与方向由生成规则的整数运算单独计算，不从 `build_rows` 或查询结果反推。读取原始 DuckDB `Decimal` 校验精确总额，再逐行以独立 SQL 核对金额分、时间、对手账号、方向、来源编号与缺失余额。主案件重复导入不得新增流水，同样的 3 笔流水在另一案件仍应独立入库。注入“已插入后回调失败”校验流水与批次同时回滚。JSON 中大整数金额分以十进制字符串保存，聚合对象另附 SHA-256。

图谱调用现有 `main.graph`，每次最多准备 2,000 笔有效唯一流水；当前样本为 257 节点、256 条聚合边。旧图谱响应的金额仍经 binary64 转换，图谱样本明确排除大金额哨兵，只校验普通金额的汇总与交易计数。Excel 使用现有 `main.export_tracked` 并计入临时文件写入，最多 10,000 笔，包含大金额哨兵；回读逐笔金额文本、前导零账号、方向与顺序，并确认待调取账号工作表存在。

## 计时与资源口径

分阶段记录 CSV 解析、`analyze`/`build_rows` 清洗、`commit_rows` 原子写入、同案重复导入去重、精确统计、两页有界分页、图谱准备和 Excel 导出。分页使用当前案件过滤和 `trade_time desc, id desc` 排序，各取首部与深偏移位置最多 100 行；统计及分页测现有业务同口径 SQL，不依赖新建 API。文件生成、应用启动、完整性核验与显式 checkpoint 也单列。worker 总计时覆盖 `run_sample` 的测量区间，包含这些阶段和准备/核验工作，解释器启动前开销与退出清理另属进程生命周期。

壁钟来自 `time.perf_counter`；CPU 来自 `time.process_time`，包含该 Python 子进程及其线程的 CPU 时间。RSS 使用 POSIX `ru_maxrss`（Windows 路径为 `PeakWorkingSetSize`），是**该完整子进程到当前阶段结束时的累计高水位**，不能当作阶段独占内存，也不能相减推算阶段用量。父进程仅收集小型聚合 JSON，不用父进程 RSS 代表子进程。Windows 分支尚未在本轮实机执行。

解析后的源 DataFrame 在清洗结束后释放；标准化行保留到重复导入和小型跨案夹具完成。图谱、分页与 Excel 均有固定上限，没有大规模浏览器布局或无限物化渲染结果。周期 checkpoint 调度器关闭，显式 checkpoint 单独计时；业务导入、事务和查询实现保持原路径。

每个阶段每个子进程只有 1 个观测值，三次重复报告中位数和 nearest-rank P95。**n=3 时 P95 就是三次最大值，只描述这些样本，不能估计稳定尾延迟。** n=1 的百万行记录只作容量观察。未丢弃预热样本；启动阶段使用空 Matplotlib 缓存，包含字体缓存构建。后续查询使用该子进程刚导入的数据库，未清空 OS 文件缓存，工作站也未锁频或独占 CPU。当前结果不满足演进建议中的 10 次冷启动/30 次预热采样规模，不据此启动技术重写或认定端到端产品性能。

## 证据边界

这是本地合成数据的 Python/SQL 工程基线。HTTP/SSE、浏览器首屏、G6 布局与交互、安装包启动、Windows 安装、真实案件和正式发布验收分别需要对应环境与入口证据。JSON 中的 `source_fingerprint` 覆盖 `app/` 下全部 Python 文件、基准 runner/CLI 和两个依赖清单；运行前后及各重复之间必须一致。源码或锁文件变化后应为新候选另行采样。
