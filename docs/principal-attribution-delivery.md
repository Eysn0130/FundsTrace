# 事件证据与本金归属施工 / 验收记录

本文保存事件与条件本金的实现边界及必要验收结果。现行语义见[事件与条件来源份额](folder-evidence-import.md#事件与条件来源份额)，金额、币种与时间见[金额契约](money-contract.md)，入口见 [CONTRIBUTING 的领域导航](../CONTRIBUTING.md#来源基础与三类领域判断)。逐轮清单、旧 Draft 状态、完整测量与首次失败保存在[固定历史正文](https://github.com/Eysn0130/FundsTrace/blob/d158cffdc0017cf2371a02c0e3d87ff207ca4611/docs/principal-attribution-delivery.md)，不作为当前候选的新检查。

## 契约与验收清单

| 层次 | 必须保持的含义 |
| --- | --- |
| 原观察、身份、事件 | 来源原金额、余额、位置和处置保留。卡账归一不证明同笔事件；通用流水号、凭证号、同秒同额不代替有作用域的事件证据。冲突、重复引用和撤回能撤销结论。确认事件没有单一账簿余额。 |
| 条件账本 | 按独立账务实体、币种及完整模型区间读取全部竞争分录，独立于上图和显示过滤。覆盖、期初、余额种类、顺序、费用／退款、冲正及透支／历史可用性需要来源依据；请求勾选、相似交易和余额吻合不补足这些事实。 |
| 精确范围与 FIFO | 范围是非空可行集的极值；只有上下界相等才是给定模型内确定份额，空可行集为冲突。FIFO 单独标为规则结果。多跳使用联合容量，独立目标上界不能相加，也不能累加中间交易额当最终本金；首次离开所选账户集合后不恢复来源标签。 |
| 未知和资源限制 | 缺证据保留 `unknown`，不一致为 `inconsistency`，超界为 `limited`。不截断竞争分录后报告完整结果。明确其他币种／区间外分录独立，不明本方或币种的竞争项不能被过滤成零。 |
| 修订和消费者 | 原“前后流水”评估来源条件，不增加默认条件表单。图、表、上下文、报告及导出沿各自明确口径和同一有效修订；来源或策略变化使旧结果／导出失效，旧修订导出返回 409，A–B–A 不恢复旧事实。 |

单账户区间最多 100,000 条分录、见证最多 500,000 单元；多账户最多 20 个账本和 20,000 个事件，核计算另有工作预算。费用及退款只有作为独立本方分录被接纳才参与，不从余额差造账。卡账与父子声明尚无有效期／换卡接续契约，冲正历史可用性也未重建；当前缺少证明真实完整覆盖、授信及外部无回流的适配。纯核或公共合成正例不能替代这些来源事实。

## 实现与兼容边界

- 原查询、表格、追踪、前后流水及导出继续承担用户操作。已确认事件与未决观察由共同投影给出范围；事件行余额为 `null`，原观察保留双方独立余额。同笔来源共享交易分组，同刻未决不按导入 ID 宣称先后。
- table／archive 完整计划以操作私有 SQLite 和有界解码缓存暂存，业务提交仍在同一 DuckDB 事务；完整财务与来源字段不以窄投影替代。旧纯 28 列专用路径曾有独立的全成员累积实现，实际调度须按保存的 profile 核对，不能外推全部路径恒定内存。
- 身份保留完整重算回退，实体、辅助声明及最终审计仍随案件增长；事件按旧新参考组和共用流水的来源闭包维护，输入有效性变化时完整回退。来源日志仍为依据，可丢弃缓存不进入案件包，不称为全部步骤均增量。
- 历史修复覆盖可空 BIGINT 经浮点化取整、缓存与真实来源绑定不一致、失败预览遗留 ready、导出内部实体 ID，以及未知币种另一方向误显示零。展示账务账号与全部来源卡的查询别名分开，不因选显示号码生成历史有效期。
- XLS 接纳保留公式、错误类型、损坏及来源路径检查；旧会话、来源和回执按冻结解析版本解释。当前新上传版本和 RAR 能力统一见[自动导入](automatic-import.md#新上传解析版本)，包格式及恢复见[导入生命周期](import-lifecycle.md#案件包格式与兼容)。历史 archive-v7 的合成 BIFF8 通过及当时 RAR5 未接纳，不应写成当前版本选择表。

## 真实格式语义核对

人民银行银发〔2019〕85号[官方附件](https://www.pbc.gov.cn/chubanwu/114566/114579/4356048/4356277/2021100915361995528.pdf)中的特定银联／网联参考号映射有请求类型及协议前提；字段名相同不证明协议版本、分配机构、唯一作用域或完整反馈，成功反馈代码不替代完整性证明。

历史窄范围核对的 12 张表、294 条记录中，22 条仅有可对应的业务类型名称，没有独立协议／作用域绑定或对向账簿正例，未升级为确认事件。1,000 项卡账声明与独立比较一致；518 项父子声明中 139 项落入 40 个多父冲突键，冲突保留。这是既有能力核对，不是新增适配成果；账面与可用余额存在差异，“交易余额”表头也不证明本笔记账后账面余额。

另冻结 14 个匿名来源案例：3 个关系正例、5 个反例、6 个未知，覆盖 63 张完整交易表、11,352 源行。1,492 个自然缺账号行没有明确补足依据。正例只证明来源明确声明的类型关系，不证明全历史实体合并、同笔事件、换卡有效期或完整本金账本；未接纳原因分类也未全部独立确认。后续真实正例仍需具体协议／参考号生命周期、对向账簿、覆盖与分页／截断证明、可靠顺序、余额类型及历史可用性来源，不能由新表头或用户勾选补造。

## 日常查询目标

以下保留原本金交付批次未达成的性能目标，供未来明确安排的性能任务对照，不作为本次精简的新验收门槛：稳定修订下，现有节点详情、边详情及有界一跳 `canvas/investigation/paths(max_hops=1)` 的 loopback HTTP 暖态 P95 ≤100 ms，新进程重开数据库后首次请求 P95 ≤500 ms。每项暖态至少 100 次、首次至少 30 次；循环不同账户／边，报告键数、样本数、P50、nearest-rank P95、最大值、条件及返回规模。启动就绪另列，不称清 OS 缓存的冷盘测试。

明细单次最多 200 条，一跳最多 100 节点／200 边；超出形状与全案分析另列成本，不能静默截断。比较只覆盖相同输入、入口及共同功能，新增证据成本分列。前端内存邻域筛选、低层解析和少量同键命中不代替 HTTP 目标；小规模 daily 的 25／8 次每端点样本也不满足这份协议。
