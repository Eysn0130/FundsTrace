# 图谱响应性与跨规模布局：复核、边界和后续施工

日期：2026-10-16。维护源码为 funds-trace，研究及探针仅用合成数据。本轮重点是研究；除下述空间索引安全防护和对应资源版本／回归外，不改变五种布局、交互锁、路由策略或业务数据。前一轮性能数字见 [性能记录](graph-layout-performance.md)，不把它们当作本轮新测量。

已授权三批施工的当前结果与新测量见 [布局响应性与结构修复交付](graph-layout-pipeline.md)。本文继续保留施工前的风险与历史证据，不将“待施工”段落当作当前实现状态。

## 1. 必须分开验收的三个目标

| 目标 | 硬约束／判断方式 | 不能据此推断 |
| --- | --- | --- |
| 业务保真 | 完整节点和边身份、端点、方向、逐币种精确金额、流水来源不变；内部 SCC／分区只服务几何 | 有限坐标、没有报错不等于易读；几何上的中心或分区不是业务主账户／团伙 |
| 几何可读 | 实体与固定下方文字、所属边的中段留缝、箭头、长边与交角；同时报告检测范围 | 一个交叉计数为零不等于实际曲线零交叉；文字均存在不等于首屏都能读清 |
| 操作响应 | 输入反馈、拖动／缩放帧间隔、单次主线程阻塞、取消生效时间、最终布局完成时间分别测量 | Worker 内核快不等于画布响应快；拆任务后能点击不等于渲染持续流畅 |

用户已确认的约束继续优先：追加不移动旧节点、不自动缩小、不进入旧交织核心；人工拖动与折点优先；节点标签固定下方 6 CSS px；简单支路右弧，简单水平关系文字在线上方，复杂关系文字固定所属线中段留缝；所有文字无底色／边框／引导线；保留顶栏和画布面积。

论文中的“有限松弛旧节点”只能作为未来用户主动整理局部／组件时的研究方向，不能自动用于追加，更不能后台悄悄改变手工位置。

## 2. 剩余性能成本：优化哪里才有效

对前一轮冻结回执 `final-1000-dagre-30.json` 再作只读汇总，30 次中位数：操作完成 398.1ms，布局 Worker 26.6ms，Fit 140.5ms，标签刷新 76.4ms，边标签同步 2970 次共 98.9ms。这些阶段相互嵌套，不能相加；此处没有重采计时。即使免掉这组场景的全部布局 Worker 时间，也只相当于总时长约 6.7%，没有依据将一次 Rust 重写承诺成整体数倍收益。

源码中的应用事务连续执行 `refreshPositions → routes/labels → viewport → Fit → route refinement → savePositions`，没有让出主线程。后台只解决了布局核计算，G6 形状、实际文字测量和最终提交仍需处理。

| 方向 | 收益来源 | 必须保留的边界 |
| --- | --- | --- |
| 同事务 dirty 集合和测量复用 | 相同字体、样式、路径、zoom 下不重复建立标签输入；Fit 到达同一倍率时复用最后一次测量 | 字体／照片／强调大小、标签成员、外部图元替换或相机变化立即失效；先保持逐字段结果与计算顺序 |
| 纯候选质量评估后台化 | 尚未动 G6 时评估节点矩形、Fit 估计和候选；降低主线程准备成本 | 仍传完整规范尺寸与视口；输出只是几何／质量；最终实际渲染门禁保留 |
| 纯路由规划与质量计算后台化 | 400 节点 dagre 的原回执中 `improveGraphRoutes` 中位约 94.9ms；部分结构有价值 | 1000 节点同布局因路由预算早退约 17.5ms，收益不是随 N 单调增长；G6 真路径／文字快照和最终七项验收仍在必要边界执行 |
| 后台交互与提交锁分离 | Worker 等待阶段允许明确的相机操作，减少“整个画布冻结”的体感 | 先定义相机、选择、几何和事实写入权限；不能简单删 pointer-events 或在原子事务中插 await |
| 有界缓存与重复提交短路 | 重复布局相同完整输入时避免计算；最终结果确实未变时避免全图施工 | 纯内核缓存与最终 G6 显示缓存分离；force 依赖初始 x/y，不能只用拓扑作 key；有界内存、按案件／画布／版本失效 |
| fallback 按时间片调度 | 避免每个微步骤都 setTimeout，也避免一个 step 吞掉整次大循环 | 时间片内保持原顺序、迭代与浮点累加；大循环增加可恢复游标；正常 Worker 和 fallback 输出对拍 |

现有材料没有证明消息复制或 JSON clone 是主要热点，不先为优化它们增加共享内存、跨源隔离或新的权限要求。Transferable 仅用于任务专属的几何缓冲，不能转走仍属于历史或当前画布的数组；账号和金额不进入浮点数组。

## 3. 已确认的交互与输入边界

### 3.1 后台等待期间的锁不一致：待施工

`canvas-editor.js` 的布局 command 进入 `history.run` 后等待 `layoutJob`，任何 `history.busy` 都给 `#graphContainer` 设置 `pointerEvents='none'`。因此普通重新布局等待 Worker 时，画布内平移、滚轮、节点鼠标事件也被关闭。

但顶栏 Fit 直接调用 `fitGraph`，仍可用；缩略图和其平移按钮位于画布容器之外，也仍能改相机。功能区 ±／100% 则被 busy 禁用。当前规则造成“同为相机操作，有些可用、有些不可用”。现有 `ownsCamera` 能保护后来变化的相机，但不是统一的交互权限规则。

施工应先显式区分 `computing / committing / idle`：计算期间可以继续显示旧的完整图，按规则允许相机；几何修改要撤销对应任务或等待，不能同时改同一候选。提交窗口保持短而完整。历史串行锁、相机权限、事实写入锁分别管理。不要直接放开所有节点拖动后指望既有 history 自动正确。

### 3.2 视口／字体测量版本：待施工

现有 job 身份、案件／画布 generation、graph/view 对象、revision 和 requestId 已有迟到保护。本轮未找到旧案件 Worker 可直接写回的反例。

但是 resize 的 `changeSize` 没有同步增加布局输入代次；Worker 可能返回按旧宽高和旧覆盖区计算的候选。字体加载也可能改变文字测量而不改变该 revision。这不改金额和方向，却会让新画布尺寸沿用旧的质量判断。

后台化前应拆分 `topologyRevision / geometryRevision / measurementRevision / viewportRevision / layoutRunId`。只携带真正使用的版本，并在快照、回包、每个让出点和最终提交前核查；相机用户操作独立判断。过期任务只能释放自己的资源，无权提交、保存，也无权回滚覆盖新任务。resize 频繁发生时合并最新请求，避免无限重启。

### 3.3 极端有限坐标导致网格循环不前进：本轮已修

损坏或人为构造快照可保留 `x=±1e19`。增量空间索引原先仅按覆盖格数决定 overflow；此时格索引超过安全整数，`x++` 可能不再改变 x，导致循环不结束。结果合法性检查位于计算之后，不能救正在运行的循环。

修复在 `geometryIndex.keys` 检查四个网格端点 `Number.isSafeInteger`，异常值走既有 overflow 扫描。不改原坐标或业务事实，不改变普通输入的格遍历顺序。公共回归覆盖极端固定点与极端障碍、正负两侧四种组合；修复前被安全的 VM 1000ms 截止检出，修复后通过。这个截止只保护测试进程，不能用作产品性能基准。

该修复只保证这处索引不会因数字不前进卡死，不代表超出安全几何范围的损坏快照可以获得正常可读排布。后续输入入场策略应明确拒绝／恢复异常显示几何，并保留原始事实；不能静默改账户、金额或让新节点看似排得正常。

## 4. 同一算法为何会在不同结构上变差

| 已复现结构 | 当前表现 | 正确解释与施工方向 |
| --- | --- | --- |
| 星形 64／65／81／160 点，显式分区 | 产生几何区分别 1／18／34／113；160 点有 112 个单点区。首块拿走 hub 后，剩余叶无法再经 hub 聚成一块 | 不是 113 个业务团体。auto 在这些样本会比较并选择 structural；显式分区应另修残余叶成批打包与高扇出空间，不悄悄换用户算法 |
| 12 点单 SCC，环按 ID 步长 1／5 连接 | 坐标相同；独立中心直线代理交叉 0／48，但凝聚块 crossingBefore/After 都为 0 | SCC 内按 ID 排圆，不看环拓扑。应识别简单环的拓扑次序；统计必须注明只看块间边。0／48 不是 G6 实际曲线交叉计数 |
| SCC 内多行关系文字 | 8 点 SCC 仅把边 labelHeight 13 改为 800，节点坐标与估计 Fit 不变 | 节点完整占位不等于所有关系文字已预留；SCC 内边被跳过，force 弹簧也主要使用 labelWidth。需要真实多币种、多行文字的关系占位与门禁反例 |
| 显式分层长链 | 宽 94、边文字宽 104、1000×700，80／160／400 点世界宽约 18264／36664／91864；400 点相机最小倍率 0.02 且 `fits=false` | 是结构长度与视口边界；保持方向不等于全图可读。不能强行压缩世界间距来骗 Fit；显式分层应提供明确概览范围和局部定位 |

以上均是可真实触发的结构边界，不泛称“节点多就会算错”。大 N 还可能触发算法路径切换、网格斥力近似、迭代预算及检测截断；高 E、最大度、SCC 大小、标签尺寸、长宽比和分量分布要分别变化，节点数不能单独决定布局。

当前重要保护继续保留：SCC／桥采用迭代栈；内核只输出节点几何；不完整碰撞比较保留基线；真实路由七项均不退步且至少一项改善才接受。主流程超过 3000 节点或 1500 边提前跳过路由精修；规划最多评估 320 条候选边，单次实际质量检查预算 120000。这是保护值，不是产品容量，不是“超过即错误”，也不代表小于该数就已全量检测。

凝聚边超过 600 时，内部交叉目标仅计算邻层逆序，SCC 内与跳层边不在该数中；质量检测的 unknown／sampled 不能显示或解释成“全图零问题”。完整边数、实际绘制数、已测覆盖与省略项需有可核查回执。

### 4.1 新增跨规模合成核矩阵：完成，但可读性并未全部通过

共 265 组公开内核探针：链、星、树、乱序环、二部汇聚、密集块、多分量、反向／自环八类，24／81／400 点分别覆盖五种布局、1024×700 和 420×700 两种视口；另以五类结构、五种布局覆盖 1000 点、755×516，最多 5567 条边。尺寸与金额哨兵均为人工合成数据。每组使用独立进程线程和安全截止，不将运行时长当作性能基准。

- 265 组均返回合法完整节点身份、未修改输入（含边端点及精确金额字符串）；24 点的 80 组同时通过重复与反转输入顺序对拍。大组未执行重复／重排对拍。
- 265 组的节点完整占位重叠检测均完成，且与独立全对枚举的计数相同。这只说明该计数正确，不能写成“零重叠通过”。
- 估计 Fit 倍率下，100 组存在节点／固定下置标签占位重叠；所有组的最小估计字体小于 12 CSS px 目标。24 点也有一个反例：密集块、显式分层、420×700，11 对完整占位相交。节点数小不等于图容易排。

| 点数 | 组合数 | 估计 Fit 下有占位重叠的组合数 |
| --- | ---: | ---: |
| 24 | 80 | 1 |
| 81 | 80 | 19 |
| 400 | 80 | 62 |
| 1000 | 25 | 18 |

这是 **内核候选与质量估计** 的边界证据：`auto` 仅执行内核的单候选，不包含主界面最多两个候选的比较；尚未执行主界面最终实测、曲线门禁、保存和 G6 渲染。估计 Fit 可低于实际相机 0.02 下限，没有真实字体字形、照片／阴影或实际曲线路径。因此不能把 100 组写成 100 个已确认的真实浏览器显示缺陷，也不能把全部小于 12px 外推为当前正常预览的文字都不达标。

它揭示了需要构造真实浏览器反例的方向：节点间距按世界坐标预留，而 6 CSS px 下方间隙在缩小时占用更多世界空间；分层长链、枢纽高扇出与多分量的包络也各有边界。后续须按“候选 → 预计 Fit → 完整占位 → 实际相机／文字／曲线”联合评估，且保持 Fit 只改相机；不能在用户每次 Fit 时偷偷重新排节点。优化只改中间环节也要回验最终实际几何。

## 6. 推荐施工次序、验收与停止条件

### 第一批：等价减少工作，并补输入与交互规则

- 先修本轮确定的数值循环缺陷；已有正常几何不能因此变化。
- 同事务共享测量／样式与 dirty 集合，消除重复 G6 施工；使用完整输入的有界缓存和重复结果短路，避免建立庞大长期缓存系统。
- 明确计算期、提交期的操作权限及测量版本；先统一 Fit、缩放、缩略图和画布权限，再逐步开放后台相机交互。
- 保存现有逐字段几何、文字、金额和方向回归，补计算中 resize／字体变化、快速 A→B→A 选择、连续点击布局、撤销和失败恢复。

### 第二批：真正后台计算，主线程短提交

- 候选纯质量评估先放入现有 Worker；再隔离路由规划和质量输入，保持采样、预算、遍历顺序、候选及逐条补救顺序。
- 主线程快照真实 G6 几何，后台生成候选；应用后只执行必要的真实门禁、标签与一次历史提交。每个异步边界校验所有权和依赖版本。
- 已有旧图时继续显示旧完整画面；不能先修改真实 G6 坐标再 await，让 Fit／缩略图／保存看见半成品。是否使用临时几何模型或隔离测量实例，要以测量一致性与额外内存实测决定，不默认复制整套 G6。
- 单次提交仍过长时，先定位实际更新量；再设计受控分帧。不能通过隐藏 all 标签、删边、减少精度或跳过门禁达到帧率。

### 第三批：独立改进结构反例，才考虑新内核

- 分别处理高扇出残余叶、简单环的拓扑顺序、多行关系标签与长链阅读范围；每类一个最小可复现反例，确认不会使其他图类退步。
- 人工几何与显式布局选择继续优先。折叠／聚合／局部松弛如成为必要能力，应由用户明确触发并显示范围、原始关系可回溯，另验保存／撤销／导出。
- 若纯力导向热点在目标设备仍占主要比例，再做 Rust/Wasm 隔离对拍；若仅剩大量图元绘制是瓶颈，再比较渲染方案。CPU、传输、内存、冷启动、字体、命中测试及离线导出一起验收。

“丝滑”应验成可测条件：输入立即反馈；计算期旧图可按权限操作；最新请求有效、取消后没有迟到覆盖；拖动缩放持续期间的帧分布；完成时间中位数／P95；最长主线程任务；稳定追加旧节点位移为零；失败保留完整合法图。60Hz 每帧约 16.7ms 是预算参考，拟将可拆 CPU 批次控制在约 4–8ms 只是工程起点，必须在目标 Windows 设备验证，不当成当前成绩或硬实时保证。

测量应覆盖首次／重复布局、布局完成后和计算期间的平移缩放，分别记录输入至下一帧反馈与最终完成；不能用“0 个超过 50ms 的长任务”代替帧率证据。按 N、E、最大度、最大 SCC、分量分布、标签尺寸、视口分别分层，并记录实际计算／检测覆盖。现阶段不把某个节点数定义为通用容量：例如 1000 点稀疏多分量和 400 点高密度图的瓶颈可以完全不同。目标设备基线不足时先记录分布，不把拟定预算写成成绩。

不能承诺任意 N/E 全部标签在固定视口同时可读、零交叉、持续 60／120 FPS 或所有启发式布局唯一正确。标签可读占位总面积超过可用屏幕时，全部可读且互不相交在几何上不可行；面积未超也不保证能排下。应保留全量事实、明确概览和局部阅读边界，不能以静默省略制造漂亮首屏。
