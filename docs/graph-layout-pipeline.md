# 布局响应性与结构修复交付

日期：2026-10-16。维护源码为 funds-trace，只使用独立合成预览与临时数据库；未改原 fund-tracker 数据，未打包。此记录接续 [三批施工计划](graph-layout-resilience.md)，历史性能记录不作为当前候选的计时证据。

## 本次行为

- 计算期间保留完整旧图，允许画布平移、滚轮缩放、Fit、缩略图定位和功能区相机命令。节点／关系几何、历史、保存与导出等写操作等待当前任务完成；提交期间保持短的同步原子事务。计算后的自动 Fit 只在用户未改相机时执行。
- 字体加载、视口尺寸或覆盖区改变会终止过期任务，合并最新输入后重算。重算继承原相机所有权，避免用户缩放后被迟到 Fit 覆盖。案件、画布、graph/view、revision、requestId 与 taskId 均在回包及提交边界校验。
- 纯文字测量采用每个 Canvas context 的有界缓存，包含内容、真实字体／整形属性与字体代次；不缓存 G6 位置。单次 Fit 复用同倍率包络，最终倍率刷新一次标签；坐标相同不重复刷新全图位置。
- 统一 Worker 协议处理纯布局、候选质量与路由建议；按任务首次加载内核，每个 graphView 最多保留一个成功完成的空闲 Worker，后续候选与路由串行复用；停止任务时销毁活动 Worker，切换画布／重建释放空闲 Worker，停放前清除任务回调。失败以相同输入恢复一次，取消、超时和结束释放 Worker。没有在半更新的 G6 事务内让出线程。
- 小图及力导向保留实际场景上的同步路由；其他布局只有本视图实测规划耗时达到 50ms 才在下次提交前后台规划，避免凭节点数预规划。力导向的下一基线会改变，上一轮规划昂贵并不能证明下一轮会通过真实质量预算。后台建议最终仍用真实 G6 曲线与文字检查七项质量。预算不完整时保留基线，规划器提前停止已确定无法验收的候选计算。未隐藏账户、关系或标签，也未降低金额精度、布局迭代次数或质量门禁。
- 分区在既有社区组内先完成拓扑遍历再分批，修复移走枢纽后大量单点批次；简单有向环按真实连接次序排布，大于 24 点时留出外周闭合通道，避免闭合边中心折线穿过第三节点；多行 SCC／力导向关系文字参与间距偏好。人工折点保持世界坐标，追加与 Fit 不借此自动移动旧节点。

固定下方 6 CSS px 的节点标签、简单支路右弧、简单水平关系上方文字、复杂关系所属线中段留缝，以及文字无底色／边框／引导线，继续使用原共享渲染规则。顶栏与画布区域未重新设计。

## 适用边界

内核合法且事实未变不等于任意密集图都可一屏读清。force 的关系长度是优化偏好；非简单 SCC 不保证全局最优交叉。分区是几何布局，不判定业务团体。固定像素的文字间距、完整图跨度与相机最小倍率可能无法同时满足，此时提示局部阅读，不篡改事实或压缩间距来制造可读性通过。

路由单次质量检查预算 120000、最多评估 320 条候选边；超过 3000 节点／1500 边跳过精修。unknown／sampled／limited 不能解释为零碰撞。这些保护值不是产品容量承诺。

主线程仍需原子更新 G6 形状和真实文字；后台化不能保证千点提交持续达到 60 FPS。本次不引入 Rust／Wasm，后续应根据残余真实渲染热点决定批次更新／渲染调度，而非以语言理论速度代替端到端证据。
