## 本轮代码修改

- 统一运行数据、授权、日志和缓存目录。保留 `FUND_DATA_DIR`、`FUND_PORT`、`fund.duckdb` 和 `.fundcase`。
- 为共享 DuckDB 连接建立操作级事务：锁覆盖整个操作，嵌套失败使外层只能回滚。
- 普通导入的案件检查、去重、批次和所有分块写入处于同一事务；后台主账号标记失败也回滚该次导入。
- 区分省略主账号选择与显式空选择，保留旧客户端缺省行为。
- 案件包严格校验 ZIP 路径、成员、Parquet 列与关联；直接重分配 ID，避免相同流水指纹映射到同一个新 ID。
- 导出使用独立临时目录和整体快照；导入照片暂存并补偿失败；删除覆盖附属表及照片，备份失败不触碰原照片。
- 追踪、画布、批次及其他附属写入校验案件存在及引用归属，防止并发删除后重新留下孤儿记录。批次删除调用同步增加 `case_id`。
- 修复有环路报告的未定义变量、字符串分析对象缺少 `re` 导入，以及 HTML 文本转义；图谱模板单次替换以保留用户数据中的字面占位符。
- 移除主页 G6 外网 fallback，使用自有 SVG 标识；没有重写前端或更换数据引擎。

## 保留的边界

- 本轮没有测试真实数据、Windows 安装包、断电恢复、百万行性能或完整浏览器矩阵。
- 数据库/照片补偿针对可处理异常；强杀或补偿本身失败仍须专项恢复设计。
- 原始上传缓存暂不随案件自动删除，须另定留存和清理策略。
- HMAC 配置缺省保持未激活。原授权配置、公开发行授权方案与许可证尚待维护者决定。
- 现有 G6 分发文件和其他来源仍须对应原始版本与许可核验，当前不是开源或发行批准。
- Rust、Polars、React 和 Tauri 只有研究与阶段门槛，没有据此改写技术栈。见 `evolution.md`。
