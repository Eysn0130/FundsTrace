# FundsTrace 金额契约

金额契约标记为 `funds-money.v1`。数据库继续使用 `DECIMAL(18,2)`，不迁移原库、不更换图引擎。计算直接取 Decimal；旧 API 与 v1 都把金额输出为固定两位十进制字符串，例如 `"9999999999999999.99"`、`"0.01"`、`"-0.01"`。缺失余额仍为 `null`。计数与允许近似的指标保持 JSON number，不能使用金额格式器格式化计数。

条件来源份额接口内部使用任意精度整数分，响应中的交易金额、最小/最大来源份额、FIFO 及分配见证仍为十进制字符串。事件金额与分录合计分开；来源本金只在指定账本条件与边界下核对，沿途交易额及各目标独立上界不能累加为本金。见[条件与证据契约](folder-evidence-import.md#事件与条件来源份额)。

| 数据 | 规则 |
| --- | --- |
| 流水、余额、方向汇总、图谱边合计、路径/环路各交易边合计、配对转出合计及差额 | 精确到分；Python Decimal，前端字符串/BigInt |
| 币种 | 独立计算；空字符串与 NULL 统一为“未标注币种”，不推定为人民币 |
| 混合币种、未标注币种或缺失来源金额的普通标量 `total` / `out_amt` / `in_amt` | 返回 `null`；改读 `amount_totals` / `out_totals` / `in_totals`；无该方向交易时为 `"0.00"` |
| 路径/环路 `total` | 各交易边合计，同一资金经多跳可能重复计入，不能当作本金或损失额 |
| 均额 | Decimal 除法后 HALF_EVEN 舍入到分，属于已舍入均额 |
| Z 分数、sigma、时间跨度、延迟、评分、显示百分比 | 允许近似或舍入，不能替代精确交易证据 |
| 容差 | 输入比例用 Decimal 做金额边界判断；输出比例是统计参数 |
| 图谱坐标、斥力、布局采样、图表像素 | 允许浮点/近似，不参与金额判断和汇总 |

`app/money.py` 拒绝把 float 冒充精确金额。旧 `/api/flows` 金额边界以字符串解析，包含等号；非有限值、需舍入的分以下金额、颠倒区间返回 422。`/api/analysis/run` 与 `/report` 金额阈值接受字符串或整数，不接受浮点金额。比例零值有效。

导入延续 HALF_UP 入库规则，例如 `0.005 → 0.01`；筛选不自动舍入。解析器 v3 完整解析科学计数，如 `1e3 → 1000.00`，不再删除未知字符拼接数字；乱码拒绝解析。既有原件和已入库记录不自动重放或重算。文件若在 Excel 保存前已丢失数字，程序不能恢复原值。

旧 API 金额从 number 升为 string 是有意的兼容变化，仓库内 G6、分析、导入预览、上下文、抽屉、导出已同步。外部消费者须改用字符串。本轮 v1 聚合金额允许 `null` 并新增 `funds` 范围；生成契约与 React 调用方同步。

专门经济事件、分析与分析导出使用 `evidence-bounded-funds-v1`，在同一选择范围内将确认事件计一次，保留未决观察覆盖。普通案件、账户和图谱使用下述有效流水统计口径，普通明细请求 events 粒度。同笔双边各 100 元计为 1 笔 / 100 元；原始两份金额和余额在来源明细中保留。通用参考号、同秒同额或 120 秒近似镜像均不能确认事件。条件事件统计给出保守上下界，无法确认的事件金额为 `null`，未知币种或金额的上界可为 `null`；不得显示为零或精确事件合计。原观察端点、金额、余额和追踪 ID 不因投影改写。专门事件分析调用方读取 `funds`；普通汇总读取对应笔数及分币种金额字段，范围与口径不同的结果不能直接比较。

综合分析使用同一投影快照。未决候选保留原观察金额用于规则线索，明确区分观察值和可确认资金范围；评分不证明资金归属。图谱/画像完整读取期间持有数据库锁；工作簿各表先在同一锁内读取，释放后构建文件。分析算法与报告概览共享快照；各币种独立应用限额与基准，`by_currency` 保留分组结果。

待调取清单以本案仍保存的 `self_account` 本方流水为账簿证据，不以自动或手工主账号角色代替。删除本方批次后，若没有其他本方流水，该账号重新进入清单；主账号角色保留。Excel 两张表中的字符串均按字面文本保存，包含以 `=` 开头的账号、户名和摘要，金额与 ID 继续保留精确字符串。

archive-v4与普通文本CSV共享已验证冲正证明时，仅按同案件、成员字节摘要和物理行直接关联，并验证实际资金摘要及本方身份；不同ZIP路径不经CSV传递归并。冲突及其见证依赖链不能提供共享，一个流水的全部真实来源关联分别有有效排除证明才排除。原始流水、来源处置和历史回执保持，金额查询与分析缺口采用同一有效证明关系；不把负数一律解释为退款或冲正，不以绝对值入账代替证明。旧v3同路径政策保持，历史重复事实不自动删除。

有明确操作关联的冲正证明仅在仍有有效来源操作时授予排除权限。撤回唯一证明来源后，仍有其他来源支持的正向原记录重新按当前证据计入；保留的 cancelled 历史日志不继续排除它。旧库无可核对操作关联的来源保留原有兼容规则，不从文件名猜补支持。

既有路径控制已接入 `/run` 和报告。未实现的拆分参数明确不可用，不用空结果冒充分析完成。

XLSX 金额、流水 ID 以文本单元格保存。Excel 只保留 15 位有效数字，不应为方便求和把大金额改回普通数值单元格。[Microsoft 说明](https://support.microsoft.com/en-us/excel/keeping-leading-zeros-and-large-numbers)。HTML 报告保留两位分位和币种，并内嵌安全转义的 `script#funds-trace-report-data` JSON（`funds-report.v1`），支持机器回读。图谱 HTML 快照保留精确源数据与标签。PNG/PDF 属视觉输出，不能作为机器回读账本。

回归涵盖相邻大金额分位、0.01/0.10/0.20、负余额、非法阈值、容差边界、币种/案件隔离、并发删改、缺失时间及 XLSX/案件包/图谱 HTML/报告 JSON 回读。入口为 `.venv/bin/python scripts/test.py`；React 构建、测试与版本化契约检查仍按根 AGENTS.md 执行。

## 有效流水与条件事件统计

常规案件、列表、账户、当前画布及边详情采用 `selected-transactions-v1`：对本案选择范围中的有效流水按 `(case_id,id)` 唯一化，具有本案完整有效证明的同笔事件在选择范围内计一次，其余流水分别保留，再由数据库 Decimal 按原币种求和。确认双边 100 元显示“1笔·¥100.00”，两笔独立同额交易显示“2笔·¥200.00”。相同金额或接近时间不提供合并权限。重复来源支持不增加同一流水；撤回和冲正遵循 effective_flows。缺金额不会补零，缺币种单独保留，不跨币种合计。该结果直接聚合有效记录，不从条件事件上界反推普通金额，也不代表已证明全部记录的现实结算或唯一性。

`funds` / `in_funds` / `out_funds` 的 `evidence-bounded-funds-v1` 及事件/本金专门分析继续保留条件范围与不确定性。全案迟到冲突会撤销同笔确认；原始记录中明确的账号、方向和金额仍用于普通明细、图、时间投影、节点／边详情和待调取清单；冲突撤销的是同笔确认及相应经济结论，不删除已追踪原行，也不带入未追踪行。普通画布、节点／边详情、普通统计及对应HTML／Excel沿用既有 `cnt`／数量字段统一显示“N笔”，不按经济状态切换单位，也不改读 `confirmed_event_count`。“笔”是普通展示约定，经济结论仍按原有证据和范围表达；既有混合 `cnt=2` 显示“2笔”，来源详情仍保留实际“3条”来源；展示金额按这些记录合计，不称为排除跨来源重复后的经济总额。过滤或只选部分来源不能隐藏该冲突。只追踪一侧时不自动追踪另一侧，但来源详情仍可核对该确认事件的双方账簿与各自余额；Excel“原始账簿观察”仅包含所选观察，主表使用相同选择范围的有效流水。画布边沿用 main 的“计数·按币种精确金额”与摘要/时间开关；Excel 主表和原始账簿保留原值，资金统计表保留事件范围。

## 交易时间与记账时间

新表格规则 v33/v34/v35、归档规则 v24/v25/v26 按明确列名区分交易时间与记账时间。两列同时存在时，资金流水只使用交易时间，记账时间另存来源依据；只有记账时间的记录保留原值与角色并列为待核对，不将其冒作交易时间。来源详情显示两类原值及所在列。旧版会话和来源按已登记的解析版本保留原解释，不自动重放或改写。

表格 v36/v37/v38、归档 v27/v28/v29 接纳带合法 ISO 显式偏移的资金记录。`flows.trade_time` 保留来源壁钟，另存 `trade_time_utc`、`trade_time_original`、`trade_time_offset`；旧库新增列为空，旧会话与回执不重解释。API 的 `trade_time` 对有区记录返回来源原文，另给壁钟、UTC、偏移和 `trade_time_basis`。来源详情保留原列、原文和微秒；非法或未知偏移不形成资金流水。

金额与成员身份不依赖共同时间轴。有区记录在 UTC 内比较，未标时区记录仅保留无区壁钟；二者混用时不声明绝对先后。无偏移筛选边界按来源壁钟日期，显式偏移边界按 UTC 且仅选有区记录；结束日期包含最后一微秒。不依据设备时区转换。混合画布可按来源壁钟筛选，但不提供共同绝对时间播放；快进快出与环路分时间依据计算，上下文和本金台账在跨依据时保留未知。同瞬间不证明同笔或先后，仍需既有强事件关联和共享账簿过账顺序证据。

同一强事件参考的双端资料，若仅因有区与无区时间缺少共同依据，记为 `unknown / time_basis_incomparable`，不当作已证矛盾。两份原始过账与余额仍保留；两份同时参与普通累计时分别保留来源记录数和按币种原金额合计，不声称已确认同笔；事件笔数与金额仍在`funds`中保留范围；单份明确命中UTC窗口时保留该份已知过账金额。双方明确UTC瞬间不同仍记为冲突，不能确认同笔。

时间窗口和播放使用 `summary.transactions` 显示与普通列表、节点、边相同的所选笔数和按币种金额，已确认双方同笔仅计一次。`funds` 的事件可行范围另行保留，不能据该范围抹去已知所选过账事实，也不把所选过账额声称为实际本金归属。

案件包须完整保留并验证已有的交易时间原文、壁钟、偏移与 UTC；无区记录保留原壁钟，不补时区。格式选择及 1–7 兼容以[案件包格式与兼容](import-lifecycle.md#案件包格式与兼容)为准。格式 1–6 保持原时间列与历史解释，不自动重放旧表格规则 v33–v35 及归档规则 v24–v26 曾拒绝的记录。

“业务时间”“时间”“date”等通用表头保留既有兼容解释，新增依据标记为来源角色未明确，不声明其为交易完成或记账时刻。已有明确完整交易时刻时，异值通用时间不覆盖它；两个明确交易时刻相互矛盾仍待核对。完整原生28列中，只有主交易号、凭证类型、凭证号同时提供有效非空值，才按各自角色校验编号；旧规则保持原解释，零元不形成资金事实。

原备注/说明列逐字声明“本文件交易时间表示受理时间，不是交易完成时间或记账时间。”时，新表格规则仅将带此声明的本行列为时间角色待核对，并保留声明和原值，不据此覆盖其他行、工作表、机构或案件，不将该用户可写备注说成平台码表。其他自由文本不作自动时间角色推断；历史固定反馈规则不因此重写。


## 负额与零额的来源记账

表格 v48–v50、归档 v39–v41 将字段已验证的负额和零额作为来源记账保留在正常流水查询、账户详情、画布选择及导出中。来源标注方向与原始带符号金额分别保留；负号、退款文字、同额或复用凭证不赋予反向资金流或抵销结论。双端点齐全时可选择来源关系，缺对手时仅保留已知本方节点。普通资金边保留原有笔数和金额标签，纯来源关系不显示金额标签；详情保留来源原值及依据。

有效资金统计继续使用原有有效交易投影。零额贡献为零；已有严格冲正配对仍排除双方重复资金，另显示其来源记录。其他负额资金影响为未确定，不将绝对值累加为支出，也不按负号反转箭头。列表及 Excel 的来源记账原值不可直接与有效交易相加认定资金总额。

本方余额差只展示同条明确前后余额的差，或同来源成员、表头区域、账号、卡号、币种及可比时间依据中唯一前一条的客观差值；按来源时间排序，与文件行序无关。缺值、无法定位的来源记录、同刻歧义或混合时间依据保留未确定。该差值不证明跨账户净流量、结算成功或某笔原交易抵销。

旧版本已完成的案件及回执不自动重放。仅重开旧案不会将旧的负额或零额审计记录补成常规流水；须明确重新导入原件，按新版本新增来源支持。旧回执保留原有解释。相同来源成员完整哈希、路径、源行及事实一致时共享来源观察；金额或编号相同不构成去重依据。


## 31 列银行反馈的双侧源过账

表格 v51–v53、归档 v42–v44 登记 `bank-feedback31-paired-postings-v1`。它只识别完整、列名唯一的原生 31 列分支，主号只作为该表族内的候选。只有同一完整成员和表头区域中双方明确本方账号精确互指、原始收付相反、同币同精确来源时刻同额、对手机构原值相同且非空、无独立日志／传票／凭证号，并且各自账簿有唯一可比前余额、两侧余额差分别等于负／正原金额时，才按一份双侧源过账计一次。不同机构、不同成员之间不据此配对；姓名相同不增加身份或同笔依据。

证明绑定原件成员哈希、源行、双侧各自的前后余额与原方向，保留双方来源和原始金额。`01` 等来源状态仍保留原解释；配对不补造成功、最终结算、最终权属或本金归因条件，也不把普通“交易余额”改称已证明的交易后账面余额。

专用证明中的 `source_primary_reference` 是来源主流水号，`source_counterparty_bank` 是来源“对手开户银行”；成员哈希只是来源位置依据，三者均不冒充签发机构、参考号渠道、业务域或明确跨账簿声明。“不详”“未知”等机构占位不提供已知机构依据。当前有效证明通过既有来源详情显示双方本方账号、原收付、目标及前余额来源行、各自前后余额和客观差值；失效或撤回后不再交付该证明。旧四字段合同的显示语义保持。

同一来源、成员和表头范围内的主号复用检查覆盖全部不同过账，不按“对手开户银行”拆成不同签发命名空间。第三条合法上下文按自己的来源含义保留，不能被两侧配对吞并；既有同过账重复支持不增加不同过账数。

每次相关导入或撤回都重判本策略，而非仅回放新增主号的旧缓存。活跃来源中主号复用、迟到第三条、缺少／冲突余额、同刻顺序未知或时区依据不一致时，保留未配对观察，不将匹配失败当成已证矛盾而删除普通流水。相同完整成员的重复来源支持不重复增加资金；原有已登记的同过账重复行契约继续适用。明确的四字段事件参考合同保持原判定逻辑。

同一实际来源成员、表头范围和已知对手机构内，主号相同、原账号互指、收付相反、同币同额且有相同时刻线索的有效过账，若余额依据不足、互相矛盾或该号被第三条复用，则只登记待核对候选。`event_members.pending_group` 是可重建的内部候选分组，不占用已确认 `event_id`，也不伪装成四字段来源声明或时区原因。全选或仅选一侧时，该组普通确定笔数和金额均为空；资金范围、原金额和两侧余额保留，不把观察合计或范围上界写成确定资金。无对应线索的普通记录及独立同方向两笔不因本规则变为待核对；混合画布的无关边保持自己的已知金额。

来源详情可核对同组候选双方及当前待核对状态；确认失效后不再显示旧配对证明。Excel 主表的待核对资金金额留空，原值完整保存在“原始账簿观察”，范围仍在“资金统计”。画布沿用已有标签开关，仅隐去不确定数值，不追加机械说明。较早的本策略草案重开时只重建派生判定，原来源、历史回执与旧解析版本不重放。

旧版会话及回执仍按原解析版本解释，仅重开不会采用本规则。明确重导原件后才新增版本化来源支持；来源操作撤回后重新计算派生配对，不改写原件或历史回执。该规则不能证明所给账簿覆盖了完整现实交易，普通未配对观察之和不因此成为结算净额。
