# FundsTrace 金额契约

金额契约标记为 `funds-money.v1`。数据库继续使用 `DECIMAL(18,2)`，不迁移原库、不更换图引擎。计算直接取 Decimal；旧 API 与 v1 都把金额输出为固定两位十进制字符串，例如 `"9999999999999999.99"`、`"0.01"`、`"-0.01"`。缺失余额仍为 `null`。计数与允许近似的指标保持 JSON number，不能使用金额格式器格式化计数。

| 数据 | 规则 |
| --- | --- |
| 流水、余额、方向汇总、图谱边合计、路径/环路各交易边合计、配对转出合计及差额 | 精确到分；Python Decimal，前端字符串/BigInt |
| 币种 | 独立计算；空字符串与 NULL 统一为“未标注币种”，不推定为人民币 |
| 混合币种旧标量 `total` / `out_amt` / `in_amt` | 返回 `null`；改读 `amount_totals` / `out_totals` / `in_totals`；无该方向交易时为 `"0.00"` |
| 路径/环路 `total` | 各交易边合计，同一资金经多跳可能重复计入，不能当作本金或损失额 |
| 均额 | Decimal 除法后 HALF_EVEN 舍入到分，属于已舍入均额 |
| Z 分数、sigma、时间跨度、延迟、评分、显示百分比 | 允许近似或舍入，不能替代精确交易证据 |
| 容差 | 输入比例用 Decimal 做金额边界判断；输出比例是统计参数 |
| 图谱坐标、斥力、布局采样、图表像素 | 允许浮点/近似，不参与金额判断和汇总 |

`app/money.py` 拒绝把 float 冒充精确金额。旧 `/api/flows` 金额边界以字符串解析，包含等号；非有限值、需舍入的分以下金额、颠倒区间返回 422。`/api/analysis/run` 与 `/report` 金额阈值接受字符串或整数，不接受浮点金额。比例零值有效。

导入延续 HALF_UP 入库规则，例如 `0.005 → 0.01`；筛选不自动舍入。解析器 v3 完整解析科学计数，如 `1e3 → 1000.00`，不再删除未知字符拼接数字；乱码拒绝解析。既有原件和已入库记录不自动重放或重算。文件若在 Excel 保存前已丢失数字，程序不能恢复原值。

旧 API 金额从 number 升为 string 是有意的兼容变化，仓库内 G6、分析、导入预览、上下文、抽屉、导出已同步。外部消费者须改用字符串。v1 既有类型不变。

图谱按付款方、收款方、精确金额和币种匹配镜像，保留原有 120 秒时间容差及秒边界，按时间、ID 顺序将尚未配对的记录一对一配对；同一本方账簿的连续多笔不相互合并。仅本方非空、严格属于付款/收款之一且双方不同的已确认账簿行参与配对；无本方、第三方本方或自转行不入队、不消耗已确认配对。每条记录最多配对一次。此规则只影响图谱显示统计，原始流水及追踪、边的流水 ID 全部保留。画像按原始流水统计；待调取导出按账号与币种分行、同币种内排序。三者统计范围不同。图谱/画像完整读取期间持有数据库锁；Excel 两张表先在同一锁内读取，释放后构建文件。综合分析只读一次流水，算法与报告概览共享快照；各币种独立应用限额与基准，`by_currency` 保留分组结果。 本次批准的身份边界修复会使曾依赖无依据配对的图谱笔数/金额增加：两笔各100元由1笔100元恢复为2笔200元；原始流水、有效事实、追踪、来源、案件统计及导入去重不变。无法证明本方的真实双账簿镜像可能显示两笔，不据此补造本方。

待调取清单以本案仍保存的 `self_account` 本方流水为账簿证据，不以自动或手工主账号角色代替。删除本方批次后，若没有其他本方流水，该账号重新进入清单；主账号角色保留。Excel 两张表中的字符串均按字面文本保存，包含以 `=` 开头的账号、户名和摘要，金额与 ID 继续保留精确字符串。

archive-v4与普通文本CSV共享已验证冲正证明时，仅按同案件、成员字节摘要和物理行直接关联，并验证实际资金摘要及本方身份；不同ZIP路径不经CSV传递归并。冲突及其见证依赖链不能提供共享，一个流水的全部真实来源关联分别有有效排除证明才排除。原始流水、来源处置和历史回执保持，金额查询与分析缺口采用同一有效证明关系；不把负数一律解释为退款或冲正，不以绝对值入账代替证明。旧v3同路径政策保持，历史重复事实不自动删除。

既有路径控制已接入 `/run` 和报告。未实现的拆分参数明确不可用，不用空结果冒充分析完成。

XLSX 金额、流水 ID 以文本单元格保存。Excel 只保留 15 位有效数字，不应为方便求和把大金额改回普通数值单元格。[Microsoft 说明](https://support.microsoft.com/en-us/excel/keeping-leading-zeros-and-large-numbers)。HTML 报告保留两位分位和币种，并内嵌安全转义的 `script#funds-trace-report-data` JSON（`funds-report.v1`），支持机器回读。图谱 HTML 快照保留精确源数据与标签。PNG/PDF 属视觉输出，不能作为机器回读账本。

回归涵盖相邻大金额分位、0.01/0.10/0.20、负余额、非法阈值、容差边界、币种/案件隔离、并发删改、缺失时间及 XLSX/案件包/图谱 HTML/报告 JSON 回读。入口为 `.venv/bin/python scripts/test.py`；React 构建、测试与版本化契约检查仍按根 AGENTS.md 执行。
