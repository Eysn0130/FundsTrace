## 每个 PR 的审查与复核

1. 读取实际候选及必要调用方，登记可出现的触发条件和正确性依据。
2. 最小完整修复，同时更新受影响调用方、公共行为回归和必要说明。
3. 对稳定 diff 独立复核，记录修复、实际检查、未覆盖边界与候选 SHA。
4. 通过 applicable required CI 后逐个合并；后一 PR 接续最新 main。新增差异重新审查。
5. 验证失败先定位原因，不降低断言或以重跑代替修复；不重复条件未变的有效检查。
