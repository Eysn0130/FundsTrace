# 自动资金数据导入

## 用户流程

原生31列的机构编码不作为银行名称的全局别名。仅新版本来源中，同一成员内具有唯一主流水、互为双方的原生过账及各自独立前余额证明，并且双方本方账号绑定到同一明确来源机构时，才将这两条观察的对手端点绑定到对方已知账簿。缺少余额证明、跨成员／机构、明确机构冲突及引用复用仍保留未决；原始编码、双方余额和旧回执不改写。旧版本来源只在显式重导提供新证明后更新当前投影，撤回新来源会撤回该证明。

选择案件后上传或追加CSV、TSV、TXT、XLSX、BIFF8 XLS及受支持的银行反馈ZIP、RAR。系统按来源结构识别字段，在每个工作表和表头区域内重新确定候选映射、单位和模式，然后校验全部记录。正常流程无需手工匹配或逐条裁决；已有高级映射和历史导入恢复仍保留。

完整原生28列表头明确区分主流水、独立凭证、传票、日志和摘要／备注；凭证种类空白不使独立编号互相冲突，主流水号字符串`0`保留，主流水缺失不借用凭证替代。摘要保留原字符，备注单独追溯。负数与零元作为来源记账保留；没有结算或冲正依据不赋予确定经济效果。币种分别保留，不补人民币或方向。完整原生28列和31列在本方、时间、币种和非负金额有效、仅缺少方向或方向码无法识别且无其他校验问题时，按独立策略`source-ledger-unoriented-v2`保留为可查询的原始观察，方向为`unknown`。原方向文本及已知对方账号、户名、银行照原值保留；账号节点沿用已有机构作用域，不按同串强并，也不赋予付款／收款角色。正额资金影响未确定，零额贡献为零，均不计普通收支，不赋予付款／收款角色或资金边。旧版本会话、回执和案件包不自动重解释，补齐旧案须显式重新上传原文件。原生28列表族不取得31列表族的双侧同笔合并权限。已知本方及对方可上图查看，缺对方时只保留本方，不生成未知对手或定向资金边。历史table-v63/v64/v65及archive-v54/v55/v56继续保留原空方向且无对方字段的v1规则。

完整原生31列表头的独立过账证明采用单独的派生规则：正额、币种、方向、端点和对手行明确，主流水在所有已知物理来源中唯一，本方账簿时间可比较且目标与最近前时刻均唯一，余额差与有向原金额相符。凭证、日志和传票保留，不因它们存在就拒绝证明。不同所有者存在同向端点、同币同额观察时，仅保留竞争可能，不能用时间差排除，也不据此合并。原有完整双边证明优先；迟到冲突撤回单笔证明，撤回来源后重新核对。来源详情显示原行、唯一前余额行和差额；这只证明本方账簿变动，不证明外部结算或最终权属。派生版本更新可重建当前投影，原始记录和历史回执不改写。

原生18/11列及已登记45/13列账户／子账户资料，可依据原任务清单的请求号、机构、精确成员路径形成有范围的卡账来源关系。无绑定、冲突和其他辅助资料保持原有处置，不按同名或近似路径合并。

RAR3/RAR5读取原始RAR字节，保留成员路径和SHA-256，并复用归档的记录、事务及回放边界。使用`rarfile==4.5`和项目`resources/rar-decoder/`内按官方发布摘要固定的7-Zip 26.05，运行时不从PATH选择解码器。原生侧车构建收集当前平台的解码器及许可；源运行需同步Python锁文件并保留这些资源。当前提供macOS和Windows x64资源；本机检查不证明Windows安装验收。加密、分卷或不完整RAR明确拒绝；不向文件系统解包成员路径，数量、实际展开量、嵌套和解码时间有界，失败不提交部分数据。完整消费还需满足声明大小及解码器成功退出；表头前缀读取不能替代该证明。

完成页分别显示来源处置、新增流水、重复流水、已配对冲回、零金额、辅助资料和未确定记录。来源自动处理完成，不表示银行材料完整，也不表示每条来源都可以唯一解释成资金事实。未确定行保留来源、原因及对金额／关系分析的影响，不按零金额处理，不伪造账号、方向、时间或金额。

完整处理报告可在当前案件内下载，包含所有逻辑记录的处置、成员／工作表、原始行位置和映射依据。原始上传文件仍按既有留存策略保护；重复事实增加来源关联，不重复计额。

## 确定性解释

- 有限的完整别名与身份角色组合产生候选；整区域的所有明确候选参与校验，不按接受率、样本前几行或模糊置信度选规则。
- 分、角、元、千元、万元按Decimal精确换算，换算后验证分精度与范围；多个金额、单位、币种、方向或时间字段必须一致。单位不跨行、字段或工作表传播。
- 明确的带符号金额字段可解释正收入／负支出。普通负金额不因负号或退款字样单独获得新方向或成对冲回语义。
- 只有限定来源的闭合交易引用、状态、身份、币种及余额等证据满足既有配对规则，才使确定的冲正／撤销双方退出有效统计。普通退款不因文字相似被排除。
- 同笔交易明确的前后账面余额可在已定义契约下补方向；普通相邻余额不能证明账簿连续，不据此补造方向或金额。
- 完整且已验证的统一交易模板允许将查询帐号／查询卡号识别为对应本方账号／卡号；普通查询条件、任务号、姓名、辅助资料或跨文件相等值不提供主体授权。

### 历史解析版本

以下记录明确 profile 的演进及其适用规则，不代表当前上传默认；仍适用的字段、歧义和冲正校验继续保留。当前入口及保存版本只在[新上传解析版本](#新上传解析版本)维护。

`funds-trace-table-v17` 引入时，普通表格从该版本进入，历史 v5—v16 保留原解释。v15 修复数字名称额外列阻挡区域换表头的问题；v16 在旧金额不可解析且新结构完整时识别日期名称的额外列；v17 继承这些能力，只增加完整标题`币种代码`的币种候选，以及旧日期／金额可解析时的局部表头歧义保护。币种候选全部参与合法值、相互一致、公式和金额单位校验，空值及无币种材料沿用历史默认。正常交易和部分标签保持原保护。银行反馈及 archive 使用各自固定版本，不能互换来源语义。

历史 BIFF8 XLS 的 `funds-trace-table-v18` 读取语义继承 v17 的确定性字段与区域保护；当时 CSV／XLSX 使用 v17，历史 v5—v17 仍拒绝 XLS，v18 不能用于其他后缀。会话重预览与提交继续使用首次固定的版本。读取前校验OLE/BIFF8子流、工作表身份和公式位置；只导入普通工作表（含隐藏表），可闭合的图表、宏表、对话表不作为交易且不执行。未知或不闭合结构、旧VBA模块子流及仅非交易工作表的输入明确拒绝；该次引入不扩展ZIP成员类型。

XLS按1900/1904日期系统解释已编码的日期、时间。非时长日期单元格的serial不少于1时保留完整日期时间，不因显示为月份或时刻而截断；1900的serial60及date格式的0至不足1不能伪造日期，1904的serial0是1904-01-01。0至不足1的明确纯时刻格式保留time，不给缺日期的数据补日期；负数、非法日期及[h]/[m]/[s]等时长不转换为交易时间，无法判明的格式不猜测。关键字段公式不采用缓存入账，错误、布尔和无法解释的日期保留`invalid_cell_type`；辅助公式不连带拒绝正常交易。共享公式仅标记实际公式单元格，不把范围中的普通字面值当作公式；数组公式按完整范围核验。文本长账号/卡号与前导零保留，数值账号继续受15位安全门槛和明确补零格式约束，不能恢复Excel已损失的数字。

完整的新表头若复用了旧身份字段位置，同时旧日期和金额也可解析，同一来源可能解释成不同的交易双方、时间和金额。table-v17 引入的区域保护不会优先猜其中一种：该行及后续受影响区域保留`ambiguous_region_header`原因，至下一无法按任何实际竞争布局的日期／金额坐标构成交易的完整明确表头恢复自动处理；额外列的数字和日期不构成新的强制门槛。其他工作表和既有明确区域不受影响。仅在额外列出现完整表头词汇仍按正常交易处理，不把合法文本账号或卡号加入黑名单。歧义区域单独作为文件首表头时只有一种既定映射，拼接后增加了另一种解释，不能在缺少边界依据时承诺两者必然产生相同资金事实。

历史 archive-v4 仅将精确“币种代码”识别和上述重叠区域保护补入原成员规则，继续使用 archive-v3 已验证的取消政策；不把整个成员解释切换为 table-v17。显式 archive-v1／v2／v3 及旧 ready 固定版本继续保留。若有 archive-v4 评估参与，同一物理来源的完整资金事实或本方身份与历史解释冲突，该次保留`conflicting_field`原因及来源，不新增或冒充重复。物理匹配限同完整ZIP成员路径，或与合格普通CSV的同字节、同行直接对应，不经普通CSV传递归并不同ZIP路径。archive-v4 已确认的币种矛盾／区域歧义也不能被旧 ready 重新接纳；历史冲突持续计入分析缺口，已有错误币种或区域解释不自动改写。此保护在已有来源详情中保存专用冲突依据，旧 ready 也可保留该依据；未参与 archive-v4 的旧表格历史冲突继续使用原有版本覆盖规则，不因同案另一份无关 archive-v4 来源改变口径。

## 入库、统计和恢复

规范流水、账户、来源关联、逐记录处置与耐久回执在同一数据库事务内写入并回读核对；失败回滚，不留下部分批次。来源原件不变，处置日志存解释及定位信息，没有新增Raw/Clean双份业务账表，也不使用运行时大模型。

同一CSV原件先单独导入、随后装入受支持ZIP时，先保留已有完整成员身份的匹配；其余记录仅在字节摘要、物理行、完整资金事实及本方身份均与同案普通CSV一致时复用旧流水。每条旧流水在本批至多复用一次，包内不同路径／物理行仍保留独立出现次数；日志继续记录完整成员路径，不重写历史事实，也不合并不同字节的相似材料。

archive-v4 引入的已闭合成对冲正证明可直接关联同案、同字节、同物理行的合格普通文本CSV，避免仅因ZIP成员改名而重复计入原交易。原交易、冲正和见证位置的实际历史事实与适用冲突均参与验证；失效证明及其见证依赖链不提供新共享，独立配对保留。共享不使两个不同ZIP路径等价；一个流水的全部来源关联分别具有排除证明时才从有效金额排除。普通CSV仅有`negative_amount`这一项诊断且对应有效冲正位置时，解除当前分析缺口，原负数处置日志、原件和旧回执不改，取消记录数仍只数ZIP实际取消评估。其他错误、未知规则、不同字节／物理行及无证明的退款负数仍保留原诊断。旧 archive-v3 案件不会因打开新版自动获得新共享，须追加适用新规则的评估；历史已存在的重复流水不删除。

原始事实、有效资金及图谱展示去重有不同口径。`effective_flows`只依据已验证排除证明筛选统计输入，原流水与来源仍可追溯。统计、账户画像、分析、追踪入口和Excel导出使用同一有效事实口径；图谱保留120秒容差与FIFO，配对仅允许明确属于交易双方的本方，详见[money-contract](money-contract.md)。图谱渲染与布局不变。缺对手的可靠流水可以保存，缺少账户身份的侧不能被猜成关系节点。

提交回执丢失或首次进度读取失败时，保留案件和导入绑定，仅查询原任务进度，不自动重放提交。主线的父级导入lease、隐藏后台保活、账户操作互斥、换案撤销及耐久回执恢复继续有效。金额含义未确定和网络结果未确定分别处理，恢复进度不要求用户裁决银行流水。

## 兼容和限制

旧数据、历史规则和已就绪会话继续可读；新解释不会覆盖已有不同资金事实。案件包的选型、校验、恢复及备份限制统一见[案件包格式与兼容](import-lifecycle.md#案件包格式与兼容)，恢复不自动重放导入。回退到旧应用应使用其能够解释的数据与备份，不能将历史规则兼容等同于旧程序能理解新增来源语义。

无后缀文本按原入口默认CSV导入并保留原名。其案件包恢复仅接纳普通非XLS规则、空工作表、恰一`table.csv`文本成员，且成员角色、编码、字节摘要和大小与来源合同闭合；随后仍执行完整日志及实际资金事实校验，不给Excel、ZIP或无日志的旧来源新增通用放行。案件包不含原件字节，这项校验不能重新鉴定缺失的原件。
